# CONTENT-GUIDE.md — 콘텐츠 철학 · 서술 규칙 · 페이지 템플릿

이 문서는 **새 콘텐츠를 쓰거나 기존 챕터를 개편할 때 따르는 표준**이다.
코드가 안 깨지게 하는 규약은 루트 `CLAUDE.md`에, *무엇을 어떤 톤으로 쓰는가*는 여기에 있다.
전 주제의 빠짐없음은 `docs/CURRICULUM.md`로 관리한다.

## 이 프로젝트가 되려는 것
> 기술 구현 매뉴얼이 아니라, **빛의 근본 원리부터 최신 렌더링 기법까지 하나의 사다리로 잇는 학습 가이드.**
> "왜 그런가(물리)"를 건너뛰지 않고, "어떻게 코딩하나(구현)"에서 끝나지 않는다.

---

## 1. 3층 원칙 (모든 주제는 세로로 관통한다)
| 층 | 질문 | 필수 요소 |
|---|---|---|
| **원리 (Why)** | 빛·물리·수학적으로 왜 그런가 | 직관 한 문장 → 다이어그램 → 수식 유도 |
| **개념 (What)** | 무엇이 일어나는가 | 만지는 인터랙티브 데모(캔버스/WebGL) |
| **구현 (How)** | 어떻게 코딩하는가 | 컴파일되는 C++/D3D11/HLSL + 함정 |

한 페이지가 세 층을 다 담을 수도, 층별로 분리될 수도 있다. 어느 쪽이든 **세 질문에 다 답이 있어야** 한다.

## 2. 표준 페이지 템플릿 (8장 사례연구가 원형)
세부 페이지는 이 순서를 지킨다:

0. **좌상단 뒤로가기만 (필수·공통, breadcrumb 바 금지)** — 모든 impl 페이지는 `<main>` 첫 줄에 뒤로가기 링크 하나만 둔다:
   `<a class="back-link" href="./index.html" onclick="if(history.length>1){history.back();return false}">← 뒤로가기</a>`
   히스토리가 있으면 이전 화면, 없으면 구현 허브로 폴백. **`.impl-topbar`(개념·데모 가이드/구현 허브/장 breadcrumb) 바는 넣지 않는다** — 페이지가 뭔지는 히어로·`<h1>`가 알려준다.
0-b. **임베드 스크립트 (필수)** — `<head>`에 `<script src="./embed.js"></script>`. 부모 iframe에 임베드되면 `html.embedded`로 크롬을 숨기고 내용 높이를 `postMessage`로 보고해 내부 스크롤이 안 생긴다. 부모(index.html)는 받은 높이로 iframe을 맞추고, 섹션 활성화 시 iframe에 `{t:"reflow"}`를 보내 데모를 다시 그리게 한다.
1. **히어로 배너** — `CLAUDE.md` 필수 규칙. 주제를 보여주는 캔버스 애니메이션 + 제목. try/catch 격리, 캔버스 크기 피드백 루프 금지.
2. **원리 (Why)** — first-principles. 수식은 반드시 앞에 직관 한 문장. 다이어그램 우선.
3. **직관 데모 (What)** — 파라미터를 만지는 인터랙티브. "슬라이더로 프레넬 보기"처럼.
4. **비교표 (Trade-offs)** — 대안 기법을 **비용·품질·적합상황**으로. 8장 "기법 한눈에 비교" 표가 표준. 산문 3문단보다 표 한 줄.
5. **구현 (How)** — 코드 블록 + `함정`/`성능` 콜아웃. 복사하면 컴파일되는 수준.
6. **언제 쓰나 / 실무 노트** — 실제 엔진(UE·Unity·Frostbite·Doom) 사례.
7. **더 읽기** — 논문·레퍼런스 링크(저자·연도 표기).

허브 페이지는 히어로 + 리드 + **비교표** + `hub-grid` 카드(세부 페이지 링크) + `page-nav`.

## 2-b. 레이아웃 규칙 — 가로 여백을 활용한다 (동적 반응형, 세로로만 길지 않게)
좁은 단일 컬럼으로 세로만 길게 쌓지 말고, 가로 폭을 쓴다. **핵심 원칙: 고정 열 수·미디어쿼리 브레이크포인트로 처리하지 말고, 가로 폭을 스스로 인식하는 폭 기반(intrinsic) 반응형으로 처리한다.** 그러면 창 크기·컨테이너 폭이 바뀌면 열 수가 자동으로 늘고 준다.

- **폭 기반 동적 열이 기본**:
  - 카드/블록 그리드 → `grid-template-columns: repeat(auto-fit, minmax(<최소폭>, 1fr))` (미디어쿼리 금지). 예: `.hub-grid`(300px), `.feature-grid`(250px), `.grid3`(260px), `.grid2`(340px).
  - 설명 리스트(`<ul>`/`<ol>`) → `columns: <최소폭>`(예: 320~340px) + `li { break-inside: avoid; }`. 폭이 넓으면 2~4열로 자동 분산되어 오른쪽 여백 낭비가 사라진다. 단계형 `ol.steps`는 제외(세로 유지).
  - 이 규칙은 이미 전역 CSS에 적용됨: 개념 트랙 `style.css`가 `.layout ... section > ul/ol`에, 구현 트랙 `impl.css`가 `.content > ul / ol:not(.steps)`에 자동 적용.
- **컨테이너 폭**: 개념 트랙 `.content`·구현 트랙 `<main class="content">` 인라인 모두 `max-width:1200px`으로 통일.
- **본문 텍스트는 폭 제한 없이 오른쪽 끝까지 꽉 채운다**(글줄 `max-width` 캡 금지). 문단·콜아웃 텍스트가 컨테이너 오른쪽 끝까지 가야 한다. *가독성 위해 좁게 묶지 말 것 — 이 프로젝트의 확정 방침.*
- **전폭 요소**: 텍스트·표(`table`/`table.impl`)·코드(`.code`)·카드그리드·히어로(`.grass-hero`)는 컨테이너 **전체 폭**.
- **데모도 전폭 + 박스 없음**: 개념 트랙 `.demo`는 `max-width:none`으로 본문·표·카드처럼 컨테이너 전폭을 쓴다. 카드 박스(테두리·배경·그림자·패딩)를 두르지 않는다(`.demo { background:none; border:none; padding:0 }`) — 캔버스만 둥근 배경을 가진 채 본문에 자연스럽게 얹힌다. 데모는 resize마다 다시 그리는 구조라 폭이 넓어져도 그림이 늘어나지 않고 가로 여유 공간만 생긴다. **특정 데모가 너무 납작하면 그 캔버스의 `height` 속성만 개별로 키운다(전폭 제한 880으로 되돌리지 말 것).**
- **레이아웃 확정 방침 — 텍스트 전폭 + 데모 아래(전폭)**: 데모가 있는 섹션은 `[제목] → [본문 텍스트 전폭] → [데모 아래·전폭]` 순으로 세로 배치한다. **텍스트와 데모를 좌우 2단(`.split`)으로 나누지 않는다**(그러면 텍스트가 절반 폭이 되어 "끝까지"가 안 됨). `.split`/`.figure`/`.col-text`는 쓰지 않는다.
- **카드로 바꿔야 할 세로 리스트**: 항목마다 제목+설명이 있는 "비교/특징 나열"은 `<ul>`보다 `.feature-grid`(제목은 `<span class="ft-name">`) 카드로 만들면 가로로 더 잘 찬다. 예: `index.html`의 렌더링 경로 5종.
- **데모 캔버스 내부**: 폭은 CSS(상한 내 100%), 높이는 `height` 속성만. 내부에서 좌측 그림 + 우측 수치/막대처럼 **가로로 정보를 배치**하면 넓은 폭을 잘 쓴다(예: `demos-paths.js`는 막대가 남은 가로 폭을 채움).
- **검증 절차(필수)**: 레이아웃을 바꾸면 헤드리스 브라우저로 실제 렌더를 확인한다. 예: `chrome --headless=new --window-size=1500,1200 --virtual-time-budget=3500 --screenshot=out.png "file:///…/index.html#섹션"`. 넓은 폭(≈1500)과 좁은 폭(≈760) 둘 다 캡처해 (1) 본문 텍스트가 오른쪽 끝까지 채워지는지 (2) 리스트/카드가 폭에 따라 열 수가 바뀌는지 (3) 가로 오버플로우가 없는지 눈으로 확인한다.

## 3. 표준 콜아웃 태그 세트 (일관성의 핵심)
기존 `.callout` 클래스를 확장해 **의미별 태그**를 고정한다. 40개 페이지의 톤이 흔들리지 않게 아래 어휘만 쓴다:

| 태그 | 클래스 | 쓰임 |
|---|---|---|
| `원리` | `callout` (기본) | 물리/수학 first-principles 요약 |
| `직관` | `callout` (기본) | 수식 앞 한 문장 직관 |
| `수식` | `callout` | 핵심 방정식과 각 항의 의미 |
| `함정` | `callout gotcha` | 자주 틀리는 지점(기존 gotcha 재사용) |
| `성능` | `callout perf` | 비용·최적화 노트(기존 perf 재사용) |
| `실무` | `callout` + `tag warn` | 실제 엔진에서 어떻게 하나 |

새 CSS 클래스를 만들지 말고 **기존 `gotcha`/`perf`/`warn` 3색을 재사용**한다. `impl.css`를 함부로 늘리지 않는 게 원칙.

### 표준 인터랙티브 데모 컨테이너 `.gdemo`
구현 페이지의 "직관 데모(What)"는 `impl.css`의 **`.gdemo` 컨테이너 + `canvas.gcanvas`(높이 360px CSS 고정) + `.gctrls/.gctl` 슬라이더 + `.hud`**를 표준으로 쓴다(6장 렌더링 경로 페이지들이 원형). 캔버스 표시 높이가 CSS로 고정돼 있으므로, 스크립트는 `getBoundingClientRect()`로 표시 크기를 읽어 `cv.width/height` 픽셀 버퍼만 갱신하면 피드백 루프가 없다. 이 세트로 충분한 데모는 새 클래스를 만들지 말 것.

### 데모 완성도 — 배너와 같은 눈높이로, GPU 우선
데모는 이 프로젝트의 핵심 학습 수단이므로 히어로 배너와 같은 완성도를 목표로 한다(상세: 루트 `CLAUDE.md` "데모 추가").
- **비주얼 주제**(조명·PBR·IBL·반사/굴절·그림자·파티클·유체·레이마칭·복셀·지형 등)는 **기본적으로 WebGL/WebGL2 셰이더로 실시간 렌더**해 화려하고 부드럽게 만든다. 슬라이더 반응이 즉각적이고, 셰이더 병렬성으로 해상도·프레임·효과가 살아 있어야 한다.
- **예외**: 픽셀 단위 알고리즘을 눈으로 해부하는 소프트 렌더(소프트웨어 래스터·레이트레이서·G-buffer 채널)나 수학·구조 2D 다이어그램은 **2D가 더 명확하므로 그대로 둔다**. 기준은 "GPU가 개념을 더 잘 보이게 하는가"이지 "무조건 WebGL"이 아니다. 2D로 남겨도 색·타이포·부드러운 갱신의 하한은 낮추지 않는다.
- **안전 규칙**: `requestAnimationFrame` + 숨김/비활성/화면 밖 정지, try/catch로 컨텍스트·셰이더 실패 시 Canvas 2D 폴백, 캔버스 크기 피드백 루프 금지(표시 크기에서 논리 크기 획득, `height` 속성 재대입 금지).

## 4. "쉽게 이해"를 강제하는 서술 규칙
- **수식 앞에는 항상 직관 한 문장.** 렌더링 방정식을 던지기 전에 "한 점의 색 = 그 점에 들어온 모든 빛을 재질 규칙대로 섞은 것".
- **물리 → 근사 → 코드 3단 착지.** ①이론적으로 뭐가 맞나 ②실시간에선 뭘 포기하나 ③그래서 코드가 왜 이렇게 생겼나. 이 연결이 "쉬움"의 정체다.
- **한 페이지 = 한 개념.** 01-math가 6개 세부로 쪼개진 것처럼 잘게 나눈다.
- **비교는 항상 표로.** "왜 forward 말고 deferred?"는 표로.
- **용어 첫 등장 시 괄호로 원어 병기** — 예: 방사도(radiance).
- **단위를 명시** — radiance는 W·sr⁻¹·m⁻² 처럼. 물리 계층의 신뢰도는 단위에서 나온다.
- **자기홍보·비학습 사족 금지.** "마음껏 코드를 열어보세요", "재미있게 즐겨보세요", "○○로 제작", "비주얼 가이드" 같은
  홍보성·감상성 문구, 푸터 태그라인, 학습에 기여하지 않는 사족은 쓰지 않는다. 모든 문장은 개념·원리·구현 이해에
  직접 기여해야 한다. 페이지 하단 브랜딩 푸터(예: "🎨 …가이드 · …제작")도 넣지 않는다.

## 5. ★ 두 트랙 동시 반영 규칙 (가장 자주 하는 실수 — 반드시 지킬 것)
이 프로젝트는 **개념 트랙**(루트 `index.html`의 `<section>` + 사이드바 + `js/demos-*.js` 데모)과
**구현 트랙**(`impl/*.html`)이 **쌍으로 존재**한다. 한 주제를 추가·개편하면 **양쪽 트랙에 모두 반영**해야 한다.
구현 페이지(impl)만 만들고 개념 트랙에 안 넣으면 **메인 페이지에는 그 주제가 안 보이는** 반쪽짜리가 된다.

새 주제 하나를 낼 때 갱신할 곳(전부 확인):
- **개념 트랙** `index.html`:
  1. 사이드바 `nav-group`에 `<a href="#새섹션">` 링크 추가
  2. 본문에 `<section id="새섹션">` 추가(설명 + `.demo` 캔버스 + `.controls`)
  3. `js/demos-*.js`에 데모 `init함수` 작성 + **`GFX.deferInit("c-캔버스id", init함수)`로 등록**(DOMContentLoaded 직접 호출 금지 — 지연 초기화로 활성 섹션만 init), `<script>` 태그 로드 확인
  4. 개념 섹션에서 대응 구현 페이지로 링크(`impl/06-paths.html` 등)
- **구현 트랙** `impl/`:
  5. 세부 페이지 `impl/0N-*.html`(표준 템플릿) + 챕터 허브 카드 + `impl/index.html` 카드
  6. 구현 페이지에서 개념 섹션(`../index.html#새섹션`)·원리 페이지로 역링크
- **문서**: `docs/CURRICULUM.md` 해당 행 상태 갱신

> 개념 트랙 데모 주의: 캔버스는 `height` 속성만 주고(폭은 CSS), `GFX.setup`이 논리 높이를 1회만 읽는다.
> 섹션은 숨겨질 때 폭이 0이므로 `resize` 리스너에서 다시 그린다(`main.js`가 섹션 활성화 시 resize를 dispatch 후 `GFX.runPendingDemos()`로 지연 init 실행). `demos-paths.js`가 표준 예시.
> 데모 등록은 `GFX.deferInit(캔버스id, init)`로만 한다 — 보이는 섹션만 초기화되고, rAF 루프는 `GFX.loop(fn, canvas)`처럼 캔버스를 넘겨 숨김 시 렌더를 건너뛴다(성능).

## 5-b. 상호 참조(원리 ↔ 개념 ↔ 구현)
- 원리(PART 0) 페이지는 그 원리를 쓰는 기법 페이지로 정방향 링크한다. 예: 프레넬 원리 → 06-pbr.
- 구현 페이지는 대응하는 개념 섹션·원리 페이지를 상단 또는 관련 콜아웃에서 링크한다.

## 6. 기술 규약 (개편 시 반드시 지킬 것 — CLAUDE.md 요약)
- 히어로/데모 캔버스: 논리 크기는 표시 크기에서 얻고 `height` 속성을 재대입하지 않는다(무한 세로 증가 버그).
- 데모 init은 대상 요소 없으면 조용히 `return`, try/catch로 격리.
- 개념 트랙 전용 CSS는 `.layout` 하위로 스코프. impl 페이지엔 영향 없음.
- D3D 규약 통일: 행벡터 `mul(v, M)`, 행 우선, 왼손 좌표계, 클립 z [0,1], 텍스처 V축 위→아래.
- JS 수정 후 `node --check`. 작업 완료 시 자동 커밋·푸시(CLAUDE.md Git 규약).
