Load vs Sample

Load · Sample · SampleBias · SampleLevel · SampleGrad · Gather · SampleCmp

텍스처 읽기 함수 — Load · Sample · Gather · SampleCmp

HLSL에서 텍스처를 읽는 방법은 하나가 아닙니다. Load는 배열 인덱싱처럼 텍셀 하나를 그대로 꺼내고, Sample은 하드웨어 샘플러로 주소 모드·필터·자동 LOD를 거쳐 재구성한 값을 줍니다. 그 사이에 LOD를 고정하는 SampleLevel, 미분을 직접 주는 SampleGrad, LOD를 미는 SampleBias, 섞지 않고 4개를 주는 Gather, 비교 후 섞는 SampleCmp가 있습니다. 이 페이지는 각 함수를 D3D11 리소스·뷰·샘플러 생성 → HLSL 호출 한 줄 → 실전 패턴(데이터 텍스처·업샘플·그림자) → 함정 순서로 구현합니다.

규약 D3D 규약으로 통일합니다: 행벡터 mul(v, M), 왼손 좌표계, 클립 z ∈ [0,1], 텍스처 V축 위→아래(좌상단이 (0,0)), 텍셀 i의 중심은 (i + 0.5) / W. 셰이더 모델은 vs_5_0/ps_5_0/cs_5_0 기준이고, SM 6.x 이후 달라지는 점은 따로 표시합니다.
전제 · 함께 보기 텍스처 업로드·SRV·UV 매핑의 큰 줄기는 03 텍스처 매핑, 밉 체인·필터 이론은 07 밉맵·필터링, sRGB는 07 감마, 그림자 전체 흐름은 06 Shadow Mapping에서 다룹니다. 손으로 만지는 2D 해부와 3D A/B 비교 데모는 개념 트랙: 텍스처 읽기 함수에 있습니다.

0. 원리 — 배열 읽기와 신호 재구성

직관 한 문장: Load는 "몇 번 칸?"에 답하고, Sample은 "이 위치·이 크기의 영역은 평균적으로 무슨 색?"에 답합니다. 텍스처를 연속 신호 f(u)의 표본 fi = f((i+0.5)/W)로 보면, 임의 위치의 값은 재구성 필터 h로 f(u) ≈ Σ fi · h(u·W − 0.5 − i)입니다. bilinear는 h가 폭 2인 삼각형(tent)인 경우이고, 축소 시에는 발자국 크기만큼 저역 통과(밉 피라미드)를 먼저 거쳐야 앨리어싱이 없습니다. Load는 이 모든 단계를 건너뛴 fi 그 자체입니다.

1. 리소스 · 뷰 · 샘플러 준비 (C++)

함수를 고르기 전에 무엇을 바인딩할지 정합니다. Load/Gather의 텍셀 해석은 SRV 포맷이, Sample*의 동작은 SamplerState가 정합니다. 시각용 텍스처는 _TYPELESS로 만들고 sRGB 뷰와 UNORM 뷰를 둘 다 만들 수 있게 해 두면, 같은 메모리를 디버그·데이터 읽기용으로 따로 해석할 수 있습니다.

texture_views.cpp — 같은 텍스처에 sRGB/UNORM 두 뷰cpp
using Microsoft::WRL::ComPtr;

// 시각용 컬러 텍스처: TYPELESS로 만들어 두 가지 해석을 허용
D3D11_TEXTURE2D_DESC td = {};
td.Width = w; td.Height = h;
td.MipLevels = 0;                                  // 전체 밉 체인
td.ArraySize = 1;
td.Format = DXGI_FORMAT_R8G8B8A8_TYPELESS;         // 뷰에서 SRGB / UNORM 선택
td.SampleDesc.Count = 1;
td.Usage = D3D11_USAGE_DEFAULT;
td.BindFlags = D3D11_BIND_SHADER_RESOURCE | D3D11_BIND_RENDER_TARGET;
td.MiscFlags = D3D11_RESOURCE_MISC_GENERATE_MIPS;
ComPtr<ID3D11Texture2D> tex;
device->CreateTexture2D(&td, nullptr, &tex);

D3D11_SHADER_RESOURCE_VIEW_DESC sd = {};
sd.ViewDimension = D3D11_SRV_DIMENSION_TEXTURE2D;
sd.Texture2D.MostDetailedMip = 0;
sd.Texture2D.MipLevels = (UINT)-1;

sd.Format = DXGI_FORMAT_R8G8B8A8_UNORM_SRGB;       // 읽을 때 sRGB→선형 (Sample·Load 모두)
ComPtr<ID3D11ShaderResourceView> srvSRGB;
device->CreateShaderResourceView(tex.Get(), &sd, &srvSRGB);

sd.Format = DXGI_FORMAT_R8G8B8A8_UNORM;            // 저장 바이트 그대로 /255
ComPtr<ID3D11ShaderResourceView> srvRaw;
device->CreateShaderResourceView(tex.Get(), &sd, &srvRaw);

샘플러는 용도별로 몇 개를 미리 만들어 슬롯에 고정해 두는 것이 일반적입니다. 아래 다섯 개면 이 페이지의 모든 함수를 커버합니다.

samplers.cpp — 용도별 SamplerStatecpp
ComPtr<ID3D11SamplerState> MakeSampler(ID3D11Device* dev, D3D11_FILTER filter,
                                       D3D11_TEXTURE_ADDRESS_MODE addr,
                                       UINT maxAniso = 1,
                                       D3D11_COMPARISON_FUNC cmp = D3D11_COMPARISON_NEVER) {
    D3D11_SAMPLER_DESC d = {};
    d.Filter = filter;
    d.AddressU = d.AddressV = d.AddressW = addr;
    d.MipLODBias = 0.0f;                 // SampleBias와 별개로 샘플러 단에서 더해지는 bias
    d.MaxAnisotropy = maxAniso;          // ANISOTROPIC 필터일 때만 의미(1~16)
    d.ComparisonFunc = cmp;              // COMPARISON_* 필터일 때만 의미
    d.BorderColor[0] = d.BorderColor[1] = d.BorderColor[2] = d.BorderColor[3] = 1.0f;
    d.MinLOD = 0.0f;
    d.MaxLOD = D3D11_FLOAT32_MAX;        // 0으로 두면 밉 0만 사용
    ComPtr<ID3D11SamplerState> s;
    dev->CreateSamplerState(&d, &s);
    return s;
}

auto sPoint   = MakeSampler(dev, D3D11_FILTER_MIN_MAG_MIP_POINT,  D3D11_TEXTURE_ADDRESS_CLAMP);
auto sLinear  = MakeSampler(dev, D3D11_FILTER_MIN_MAG_MIP_LINEAR, D3D11_TEXTURE_ADDRESS_WRAP);   // trilinear
auto sAniso   = MakeSampler(dev, D3D11_FILTER_ANISOTROPIC,        D3D11_TEXTURE_ADDRESS_WRAP, 16);
auto sClamp   = MakeSampler(dev, D3D11_FILTER_MIN_MAG_MIP_LINEAR, D3D11_TEXTURE_ADDRESS_CLAMP);  // 포스트·LUT
// 그림자: 비교 + 선형 = 하드웨어 2×2 PCF. Border=1(빛 받음)로 맵 밖을 밝게
auto sShadow  = MakeSampler(dev, D3D11_FILTER_COMPARISON_MIN_MAG_LINEAR_MIP_POINT,
                            D3D11_TEXTURE_ADDRESS_BORDER, 1, D3D11_COMPARISON_LESS_EQUAL);

ID3D11SamplerState* all[] = { sPoint.Get(), sLinear.Get(), sAniso.Get(), sClamp.Get(), sShadow.Get() };
ctx->PSSetSamplers(0, 5, all);   // s0~s4
ctx->VSSetSamplers(0, 5, all);   // VS에서 SampleLevel을 쓸 때
ctx->CSSetSamplers(0, 5, all);
성능 샘플러 객체는 드라이버가 해시로 중복 제거하지만, 매 드로우마다 CreateSamplerState를 부르는 것은 피하세요. D3D11은 스테이지당 16 슬롯, D3D12는 정적 샘플러(루트 시그니처)로 고정하는 것이 관례입니다. Load만 쓰는 셰이더는 샘플러 슬롯이 아예 필요 없습니다.

2. Load — 정수 좌표로 텍셀 하나

Load는 밉·배열 인덱스까지 포함한 정수 주소를 받습니다. 좌표 차원이 하나 더 붙는 이유는 마지막 성분이 mip이기 때문입니다. operator[]는 밉 0 전용 단축형이고, mips[m][xy]로 다른 밉도 읽을 수 있습니다.

load.hlsl — 형태별 Loadhlsl
Texture2D<float4>      gAlbedo   : register(t0);
Texture2D<float>       gDepth    : register(t1);
Texture2DArray<float4> gLayers   : register(t2);
Texture2DMS<float4, 4> gMSAA     : register(t3);
Buffer<float4>         gPoints   : register(t4);   // 1D 데이터는 버퍼도 후보

float4 LoadExamples(float4 svPos : SV_Position) : SV_Target
{
    int2 p = int2(svPos.xy);                        // 화면과 1:1인 버퍼: 픽셀 중심(x+0.5)을 버림 → 정확한 텍셀

    float4 a  = gAlbedo.Load(int3(p, 0));           // (x, y, mip)
    float4 a2 = gAlbedo[p];                         // 위와 동일(밉 0)
    float4 a3 = gAlbedo.mips[2][p >> 2];            // 밉 2: 해상도가 1/4이므로 좌표도 >> 2
    float4 o  = gAlbedo.Load(int3(p, 0), int2(1, 0)); // 즉시 오프셋 [-8, 7]

    float  z  = gDepth.Load(int3(p, 0));            // 깊이 SRV(R24_UNORM_X8_TYPELESS 등)는 .r 한 채널
    float4 l  = gLayers.Load(int4(p, 3, 0));        // (x, y, 배열 슬라이스, mip)
    float4 s2 = gMSAA.Load(p, 2);                   // 2번 MSAA 샘플(밉 없음)
    float4 b  = gPoints.Load(17);                   // 버퍼: 요소 인덱스

    // 크기 조회 — UV → 텍셀 변환에 필요
    uint W, H, mipCount;
    gAlbedo.GetDimensions(0, W, H, mipCount);
    return a;
}

// UV를 이미 가진 경우의 Load: floor(uv * size) — round가 아니다
float4 LoadAtUV(Texture2D<float4> t, float2 uv, uint mip)
{
    uint W, H, n; t.GetDimensions(mip, W, H, n);
    int2 ip = int2(floor(uv * float2(W, H)));
    ip = clamp(ip, int2(0, 0), int2(W - 1, H - 1));  // 범위 밖은 0이 오므로 필요하면 직접 clamp
    return t.Load(int3(ip, mip));
}
함정 ① 범위 밖 Load는 0을 반환합니다(D3D10+ 정의된 동작). 주소 모드가 없으니 가장자리 커널(블러·Sobel)은 직접 clamp해야 합니다. ② int2(uv * W)는 음수 uv에서 0 쪽으로 잘립니다(−0.3 → 0). 음수가 가능하면 floor를 먼저 쓰세요. ③ 텍스처 크기를 상수버퍼에 하드코딩하지 말고 GetDimensions를 쓰세요. 해상도 스케일·밉 변경 시 바로 깨집니다. ④ Load는 "필터가 없어서" 시각용 텍스처를 축소해 그리면 지글거립니다. 개념 트랙 3D 바닥 데모의 A 쪽이 그 모습입니다.

3. Sample · SampleBias · SampleLevel · SampleGrad

네 함수는 같은 샘플러 경로를 타고 LOD를 어디서 얻느냐만 다릅니다. Sample/SampleBias는 쿼드(2×2 픽셀)의 이웃 차이로 미분을 구하므로 픽셀 셰이더 전용이고, SampleLevel과 SampleGrad는 호출자가 LOD 정보를 주므로 어느 단계에서나 됩니다.

sample_family.hlslhlsl
Texture2D    gTex    : register(t0);
SamplerState sLinear : register(s1);
SamplerState sAniso  : register(s2);

float4 PS(float2 uv : TEXCOORD0) : SV_Target
{
    float4 c0 = gTex.Sample(sAniso, uv);                    // 자동 LOD(미분) + 샘플러 필터
    float4 c1 = gTex.Sample(sAniso, uv, int2(1, 0));        // 텍셀 단위 즉시 오프셋
    float4 c2 = gTex.SampleBias(sLinear, uv, -0.5);         // λ - 0.5 → 조금 더 선명(그리고 더 지글)
    float4 c3 = gTex.SampleLevel(sLinear, uv, 3.0);         // λ = 3 고정(미분 무시)
    float2 dx = ddx(uv), dy = ddy(uv);
    float4 c4 = gTex.SampleGrad(sLinear, uv, dx, dy);       // = Sample과 같은 결과(미분을 직접 줬을 뿐)

    float  lod  = gTex.CalculateLevelOfDetail(sLinear, uv);           // 하드웨어가 고를 λ(클램프 후)
    float  lodU = gTex.CalculateLevelOfDetailUnclamped(sLinear, uv);  // 클램프 전 λ
    return c0;
}

3-1. 정점·컴퓨트 셰이더에서는 SampleLevel

정점 셰이더에는 쿼드가 없으니 미분도 없습니다. 하이트맵 디스플레이스먼트처럼 VS에서 텍스처를 읽을 때는 LOD를 직접 줍니다. 컴퓨트에서 리샘플링(크기가 다른 버퍼로 옮기기)할 때도 마찬가지입니다.

vs_displace.hlsl / cs_resample.hlslhlsl
Texture2D<float> gHeight : register(t0);
SamplerState     sClamp  : register(s3);
cbuffer CB : register(b0) { float4x4 gWVP; float gScale; float2 gInvOut; }

struct VSIn { float3 pos : POSITION; float2 uv : TEXCOORD0; };
float4 VS(VSIn i) : SV_Position
{
    float h = gHeight.SampleLevel(sClamp, i.uv, 0);      // VS에서 Sample()은 컴파일 에러: 미분이 없다
    float3 p = i.pos + float3(0, h * gScale, 0);
    return mul(float4(p, 1), gWVP);
}

Texture2D<float4>   gSrc : register(t1);
RWTexture2D<float4> gDst : register(u0);
[numthreads(8, 8, 1)]
void CSResample(uint3 id : SV_DispatchThreadID)
{
    float2 uv = (id.xy + 0.5) * gInvOut;                 // 출력 텍셀 중심 → 입력 UV
    gDst[id.xy] = gSrc.SampleLevel(sClamp, uv, 0);       // bilinear 리샘플
}

3-2. UV가 불연속일 때 SampleGrad — 아틀라스 이음새 없애기

텍스처 아틀라스의 한 타일을 frac()로 반복하면 타일 경계에서 uv가 1→0으로 튑니다. 쿼드 이웃 차이가 거의 1(=텍스처 전체)이 되어 λ가 최상위 밉으로 치솟고, 경계마다 1픽셀 두께의 선이 생깁니다. 미분은 연속인 좌표로 구해서 넘기면 됩니다.

atlas_tile.hlslhlsl
float4 SampleAtlasTile(Texture2D atlas, SamplerState s, float2 worldUV,
                       float2 tileOrigin, float2 tileSize, float2 padTexels, float2 atlasSize)
{
    // 미분은 frac 전에, 아틀라스 스케일로: 연속 좌표 → 이음새 없음
    float2 dx = ddx(worldUV) * tileSize;
    float2 dy = ddy(worldUV) * tileSize;

    // 패딩만큼 안쪽으로 줄여 이웃 타일이 bilinear로 번지지 않게
    float2 pad   = padTexels / atlasSize;
    float2 inner = tileSize - 2.0 * pad;
    float2 uv    = tileOrigin + pad + frac(worldUV) * inner;

    return atlas.SampleGrad(s, uv, dx, dy);
}
함정 분기 안의 Sample: 쿼드의 일부 픽셀만 들어가는 if 안에서 Sample을 부르면 미분이 정의되지 않습니다(SM5에서는 컴파일러가 분기를 펼치거나 경고). ddx/ddy는 분기 밖에서 구해 두고 안에서는 SampleGrad를 부르세요. discard된 픽셀도 이웃의 미분 계산을 위해 "헬퍼 픽셀"로 계속 실행될 수 있습니다(출력은 쓰지 않음).
실무 트라이플래너 매핑, 시차(parallax) 매핑, 구면 좌표(위경도 텍스처의 경도 이음새), 가상 텍스처의 페이지 경계가 모두 같은 문제를 같은 방식(SampleGrad)으로 풉니다. TAA·DLSS·FSR 같은 업스케일러를 쓸 때는 내부 해상도가 낮으므로 엔진이 MipLODBias = log2(내부/출력)(음수)를 샘플러에 걸어 출력 해상도 기준의 선명도를 맞춥니다.

4. Gather — 2×2를 섞지 않고

Gather는 bilinear가 쓸 4텍셀에서 한 채널을 받아옵니다. 반환 순서는 x = (u0, v1) 왼쪽아래, y = (u1, v1) 오른쪽아래, z = (u1, v0) 오른쪽위, w = (u0, v0) 왼쪽위이고, 여기서 v1은 V축이 아래로 커지는 D3D 관례에서 아래 행입니다. 항상 밉 0을 읽습니다(다른 밉이 필요하면 그 밉만 가리키는 SRV를 만듭니다).

gather.hlsl — 순서 확인 · 직접 bilinear · 깊이 인지 업샘플hlsl
Texture2D<float>  gDepthHalf : register(t0);   // 하프 해상도 깊이
Texture2D<float4> gAOHalf    : register(t1);   // 하프 해상도 AO(R 채널)
Texture2D<float>  gDepthFull : register(t2);
SamplerState      sPointClamp: register(s0);

// Gather 4값으로 bilinear를 직접 재현 — Sample(Linear)과 같은 값
float BilinearFromGather(Texture2D<float> t, SamplerState s, float2 uv, float2 size)
{
    float4 g = t.GatherRed(s, uv);              // x: 왼쪽아래 y: 오른쪽아래 z: 오른쪽위 w: 왼쪽위
    float2 f = frac(uv * size - 0.5);           // 하드웨어와 같은 소수부
    float top    = lerp(g.w, g.z, f.x);
    float bottom = lerp(g.x, g.y, f.x);
    return lerp(top, bottom, f.y);
}

// 깊이 인지(joint bilateral) 업샘플: 풀해상 깊이와 비슷한 저해상 텍셀에 가중치
float UpsampleAO(float2 uv, int2 fullPix, float2 halfSize)
{
    float  zFull = gDepthFull.Load(int3(fullPix, 0));
    float4 zLow  = gDepthHalf.GatherRed(sPointClamp, uv);
    float4 ao    = gAOHalf.GatherRed(sPointClamp, uv);

    float2 f = frac(uv * halfSize - 0.5);
    float4 wb = float4((1 - f.x) * f.y, f.x * f.y, f.x * (1 - f.y), (1 - f.x) * (1 - f.y)); // x y z w 순
    float4 wz = 1.0 / (abs(zLow - zFull) * 1000.0 + 1e-3);    // 깊이가 다르면 가중치↓
    float4 w  = wb * wz;
    return dot(ao, w) / dot(w, 1.0);
}

// Hi-Z: 2×2 최대 깊이(역 Z면 최소) 한 번에
float HiZMax(Texture2D<float> t, SamplerState s, float2 uvCenterOf2x2)
{
    float4 g = t.GatherRed(s, uvCenterOf2x2);   // uv를 4텍셀의 공통 꼭짓점에 둔다
    return max(max(g.x, g.y), max(g.z, g.w));
}
성능 단일 채널 컨볼루션(깊이·AO·마스크)은 Gather 1회가 Load 4회를 대체합니다. 4×4 영역이면 Load 16회 → Gather 4회입니다. 오프셋 버전 GatherRed(s, uv, int2 o0, o1, o2, o3)(SM5)로 쿼드 4개를 각자 다른 오프셋에서 받을 수도 있습니다. RGBA를 다 써야 하면 채널별 Gather 4회 = Load 4회로 이득이 없습니다.

5. SampleCmp · SampleCmpLevelZero · GatherCmp — 그림자

비교 샘플러(SamplerComparisonState)는 4텍셀 각각에 ref ComparisonFunc texel을 적용해 0/1을 만든 다음, 그 결과를 필터합니다. 결과는 "4텍셀 중 빛을 받는 비율"이고, 이것이 하드웨어 2×2 PCF입니다. 그림자맵에는 밉이 없으므로 SampleCmpLevelZero가 표준입니다. 미분이 필요 없어 분기 안·VS·CS 어디서나 됩니다.

shadow_pcf.hlsl — 1회 · N×N · GatherCmp 가중hlsl
Texture2D<float>       gShadow : register(t5);   // R32_TYPELESS 리소스의 R32_FLOAT SRV
SamplerComparisonState sShadow : register(s4);   // COMPARISON_MIN_MAG_LINEAR_MIP_POINT, LESS_EQUAL

// (a) 하드웨어 2×2 PCF — 호출 1회
float ShadowHW(float3 sh)                         // sh = (uv, 빛 공간 깊이 - bias)
{
    return gShadow.SampleCmpLevelZero(sShadow, sh.xy, sh.z);
}

// (b) N×N PCF — 각 탭이 이미 2×2 PCF라 경계가 부드럽다
float ShadowPCF(float3 sh, float2 texel, int R)
{
    float sum = 0;
    [unroll] for (int y = -R; y <= R; ++y)
    [unroll] for (int x = -R; x <= R; ++x)
        sum += gShadow.SampleCmpLevelZero(sShadow, sh.xy + float2(x, y) * texel, sh.z);
    return sum / ((2 * R + 1) * (2 * R + 1));
}

// (c) GatherCmp — 비교 결과 4개를 받아 텐트 가중치를 직접 준다(넓은 커널을 적은 호출로)
float ShadowGatherCmp(float3 sh, float2 size)
{
    float2 f = frac(sh.xy * size - 0.5);
    float4 c = gShadow.GatherCmpRed(sShadow, sh.xy, sh.z);   // 각 성분 0 또는 1
    float top = lerp(c.w, c.z, f.x), bottom = lerp(c.x, c.y, f.x);
    return lerp(top, bottom, f.y);                            // = (a)와 같은 값. 여기에 원하는 가중을 더한다
}

// (d) 비교 샘플러 없이 Load로 — 계단이 남는다(개념 트랙 그림자 데모의 A)
float ShadowLoad(float3 sh, float2 size)
{
    float z = gShadow.Load(int3(sh.xy * size, 0));
    return sh.z <= z ? 1.0 : 0.0;
}

함정 ① 비교 샘플러는 SamplerComparisonState 타입으로 선언해야 합니다. 일반 SamplerState로 선언하면 같은 슬롯이라도 비교가 일어나지 않습니다. ② 지원 포맷은 단일 채널(R32_FLOAT, R24_UNORM_X8_TYPELESS, R16_UNORM)뿐입니다. ③ PCF 커널이 넓을수록 오프셋 탭이 기울어진 수신면의 다른 깊이를 비교하므로 shadow acne가 늘어납니다. 기울기 바이어스(SlopeScaledDepthBias)나 수신면 기울기 기반 바이어스를 같이 키우세요.

6. 실전: 데이터 텍스처로 수천 마리 물고기 — 왜 Load인가

군집 애니메이션은 경로(스플라인 제어점)를 텍스처에 넣고, 인스턴스마다 경로상의 위치 t를 정점 셰이더에서 평가합니다. 여기서 Sample을 쓰면 ① 하드웨어는 선형 보간뿐이라 꺾인 경로가 되고 ② 텍셀 중심(+0.5)을 놓치면 이웃 점이 평균되며 ③ 필터 가중치 정밀도 때문에 미세한 계단이 생기고 ④ 밉이 있으면 경로가 쪼그라듭니다. Load로 제어점 4개를 정확히 읽고 곡선은 셰이더가 계산합니다.

fish_vs.hlsl — Load ×4 + Catmull-Romhlsl
Texture2D<float4> gPath : register(t0);      // 가로 = 제어점, 세로 = 경로 번호. R32G32B32A32_FLOAT, 밉 1개
cbuffer CB : register(b0) { float4x4 gVP; float gTime; uint gNumPoints; }

struct Inst { float phase; float speed; uint path; float scale; };
StructuredBuffer<Inst> gInst : register(t1);

float3 CatmullRom(float3 p0, float3 p1, float3 p2, float3 p3, float t)
{
    float t2 = t * t, t3 = t2 * t;
    return 0.5 * (2 * p1 + (-p0 + p2) * t + (2 * p0 - 5 * p1 + 4 * p2 - p3) * t2 + (-p0 + 3 * p1 - 3 * p2 + p3) * t3);
}

float3 PathPos(uint path, float t)                  // t ∈ [0, N): 닫힌 경로
{
    int  N  = (int)gNumPoints;
    int  i  = (int)floor(t);
    float f = t - i;
    int4 k  = (int4(i - 1, i, i + 1, i + 2) % N + N) % N;   // 수동 Wrap (Load엔 주소 모드가 없다)
    float3 p0 = gPath.Load(int3(k.x, path, 0)).xyz;
    float3 p1 = gPath.Load(int3(k.y, path, 0)).xyz;
    float3 p2 = gPath.Load(int3(k.z, path, 0)).xyz;
    float3 p3 = gPath.Load(int3(k.w, path, 0)).xyz;
    return CatmullRom(p0, p1, p2, p3, f);
}

float4 VS(float3 local : POSITION, uint iid : SV_InstanceID) : SV_Position
{
    Inst in0 = gInst[iid];
    float t  = fmod(in0.phase + gTime * in0.speed, (float)gNumPoints);
    float3 p = PathPos(in0.path, t);
    float3 fwd = normalize(PathPos(in0.path, t + 0.02) - p);
    float3 side = normalize(cross(float3(0, 1, 0), fwd));
    float3 up = cross(fwd, side);
    float3 world = p + (local.x * side + local.y * up + local.z * fwd) * in0.scale;
    return mul(float4(world, 1), gVP);
}

8. 실무 노트 — 엔진에서는 어떻게 하나

  • Unreal Engine — 셰이더 코드에서는 Texture2DSample·Texture2DSampleLevel·Texture2DSampleGrad(Common.ush) 같은 래퍼를 쓰고, 머티리얼 노드는 "MipValueMode"(None/MipLevel/MipBias/Derivative)로 Sample/SampleLevel/SampleBias/SampleGrad를 고릅니다. 버텍스 단계(WPO)에서 읽는 텍스처는 미분이 없으므로 SampleLevel 계열로 컴파일됩니다. 해상도 스케일링·TSR 사용 시 엔진이 음의 MipBias를 자동으로 걸어 줍니다.
  • Unity SRP — Core ShaderLibrary의 LOAD_TEXTURE2D, SAMPLE_TEXTURE2D, SAMPLE_TEXTURE2D_LOD, SAMPLE_TEXTURE2D_GRAD, GATHER_RED_TEXTURE2D, SAMPLE_TEXTURE2D_SHADOW 매크로가 각 API의 해당 함수로 내려갑니다.
  • VAT(Vertex Animation Texture) — Houdini 등에서 구운 위치·노멀 텍스처는 sRGB 끄기, 압축 끄기, 밉 끄기, Point/Load로 읽기가 공통 지침입니다. 이 페이지 6장의 문제가 그대로 생기기 때문입니다.
  • 디퍼드 라이팅·포스트 체인 — G-buffer는 화면과 1:1이라 Load(int3(SV_Position.xy, 0))가 표준이고, 해상도가 다른 버퍼(하프 해상도 SSAO·볼류메트릭)만 Gather/SampleLevel로 업샘플합니다.
  • 그림자 — 거의 모든 엔진이 SampleCmpLevelZero 기반 PCF(또는 Gather 기반 가중 PCF)를 쓰고, 소프트 섀도는 PCSS처럼 블로커 탐색에 일반 Gather/Load, 필터에 비교 샘플을 섞습니다.
