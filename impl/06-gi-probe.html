Irradiance 프로브(SH) · 프로브 그리드 · DDGI — 한 줄 한 줄 직접 구현

라이트맵은 정적 표면에만 GI를 붙일 수 있습니다. 걸어다니는 캐릭터 같은 동적 물체도 GI를 받으려면 공간 자체를 샘플해야 합니다. 그 해법이 Irradiance 프로브입니다 — 공간 곳곳에 프로브를 놓아 방향별 간접광을 구면 조화(SH) 9계수로 압축 저장하고, 물체는 가까운 프로브들을 보간해 씁니다. 이 페이지에서는 SH 기저 평가·복원, 프로브를 격자로 깔아 삼선형 보간하는 법, 그리고 그 최대 약점인 빛 누수를 DDGI의 가시성 저장으로 없애는 데까지 한 줄씩 만들어 봅니다.

규약 행벡터 v' = v * M(HLSL mul(v, M)), 행 우선, 왼손 좌표계, 클립 z ∈ [0,1], 텍스처 V축 위→아래. 코드는 원리 학습용으로 최소 형태만 남겼습니다. 이 페이지는 간접 디퓨즈 GI를 다루며, 간접 스페큘러는 IBL · 리플렉션 프로브에서 다룹니다.

직관 데모 — 그리드 보간과 빛 누수, 그리고 DDGI

위에서 내려다본 평면도입니다. 왼쪽은 밝은 방(따뜻한 빛), 오른쪽은 어두운 방이고 가운데 벽이 둘을 가릅니다. 규칙적으로 깔린 프로브(점)는 각자 자기 위치의 간접광 색을 담습니다. 물체를 드래그하면 그 물체를 감싼 4개 최근접 프로브가 켜지고, 셀 안 상대 위치로 만든 이중선형 가중 (3D에선 삼선형)으로 네 색을 섞어 물체를 칠합니다. 각 프로브→물체 선의 굵기가 그 프로브의 몫입니다.

물체를 어두운 방으로 옮긴 뒤 가시성 가중을 꺼 보세요 — 벽 반대편(밝은 방) 프로브까지 보간에 끌려와 어두워야 할 물체가 새어(누수) 밝아집니다. 가시성 가중을 켜면 벽 뒤 프로브의 몫이 0에 가까워져 누수가 사라집니다. 이것이 DDGI가 프로브에 거리(가시성)를 함께 저장해 푸는 문제입니다.

물체를 드래그하세요

물체(흰 원)를 드래그. 켜진 4개 프로브의 가중치 합은 1입니다. 어두운 방에서 가시성 가중을 끄면 누수가, 켜면 벽 뒤 프로브가 배제되어 정상 그늘이 됩니다.

Irradiance 프로브 — 구면 조화(SH)로 방향별 간접광 압축

무엇을 만드나: 공간 곳곳에 "프로브"를 놓고, 각 프로브가 자기 위치에서 모든 방향으로 들어오는 간접광을 아주 적은 계수(보통 9개)로 압축 저장합니다. 런타임에는 동적 물체가 가까운 프로브들을 보간해 자기 법선 방향의 간접광을 즉시 얻습니다. 왜 필요한가: 라이트맵은 정적 표면에만 붙지만, 프로브는 공간 자체를 샘플하므로 걸어다니는 캐릭터 같은 동적 물체도 GI를 받을 수 있습니다.

핵심 도구는 구면 조화 함수(Spherical Harmonics, SH)입니다. SH는 구면 위의 함수(방향→값)를 푸리에 급수처럼 기저 함수들의 가중합으로 전개합니다. 부드러운 irradiance는 저차(low-frequency)라서 2차(9개 계수)만으로 놀랍도록 정확하게 표현됩니다.

1. 방향 하나로 SH 기저 9개 평가 (HLSL)

sh_basis.hlslhlsl
// 단위 방향 dir로 실수형 SH 기저(l=0..2, 총 9개)를 평가한다.
void EvalSH9(float3 dir, out float sh[9])
{
    float x = dir.x, y = dir.y, z = dir.z;

    // l = 0 (상수항, 방향과 무관)
    sh[0] = 0.282095;                       // 1/(2√π)

    // l = 1 (선형항: 방향 성분에 비례)
    sh[1] = 0.488603 * y;                   // -√(3/4π)·y 계열
    sh[2] = 0.488603 * z;
    sh[3] = 0.488603 * x;

    // l = 2 (2차항: 성분들의 곱)
    sh[4] = 1.092548 * x * y;
    sh[5] = 1.092548 * y * z;
    sh[6] = 0.315392 * (3.0 * z * z - 1.0);
    sh[7] = 1.092548 * x * z;
    sh[8] = 0.546274 * (x * x - y * y);
}

시그니처·문법 해부

void EvalSH9(float3 dir, out float sh[9]): HLSL에는 참조가 없으니 결과를 돌려줄 때 out 한정자를 씁니다 — 함수가 sh 배열을 채워서 호출자에게 되돌려준다는 뜻입니다. float sh[9]는 9개짜리 고정 크기 배열입니다(2차 SH의 계수 개수 = (l+1)² = 3² = 9). dir은 반드시 단위벡터여야 합니다 — 아래 다항식들이 단위 구면 위에서 정의되기 때문입니다.

수학 → 기하 직관 → 코드 매핑

수학: SH 기저는 라플라스 방정식의 구면 해로, 차수 l마다 2l+1개가 있습니다 (l=0 → 1개, l=1 → 3개, l=2 → 5개, 합 9개). 각 상수(0.282095 등)는 기저가 구면 위에서 직교·정규가 되도록 맞추는 정규화 상수입니다. 예를 들어 0.282095 = 1/(2√π)입니다.

기하 직관: l=0 항은 방향과 무관한 평균 밝기(전체를 균일하게 채우는 빛)입니다. l=1 세 항(x, y, z에 비례)은 한쪽이 밝고 반대쪽이 어두운 기울기 — 즉 지배적인 빛의 방향입니다. l=2 다섯 항은 더 미세한 "언덕과 골짜기" 패턴을 담습니다. 저차만 쓰면 뭉툭하지만 부드러운 GI에는 충분합니다.

코드 매핑: sh[0]은 상수, sh[1..3]은 방향 성분에 정확히 비례, sh[4..8]은 성분들의 이차 곱(xy, yz, 3z²−1, xz, x²−y²)입니다. 이 형태는 SH 실수 기저의 표준 공식을 그대로 옮긴 것입니다.

2. 프로브가 저장한 SH로 법선 방향 irradiance 복원 (HLSL)

베이킹 때 각 프로브는 위 기저로 3채널(RGB) × 9계수 = 27개 float을 저장해 둡니다. 런타임에는 표면 법선 n에 대해 다시 SH를 평가하고, 저장된 계수와 내적하면 그 방향의 간접광이 나옵니다.

probe_sample.hlslhlsl
cbuffer ProbeCB : register(b3)
{
    float4 gSH_R[9];   // R채널 9계수 (.x만 사용, 정렬용 float4)
    float4 gSH_G[9];
    float4 gSH_B[9];
};

// 표면 법선 n으로 프로브의 간접광(RGB)을 복원한다.
float3 SampleProbeIrradiance(float3 n)
{
    float basis[9];
    EvalSH9(n, basis);                 // 법선 방향의 기저값 9개

    float3 result = 0;
    [unroll]
    for (int i = 0; i < 9; ++i)
    {
        // 각 계수 · 해당 기저값을 채널별로 누적 = SH 내적(재구성)
        result.r += gSH_R[i].x * basis[i];
        result.g += gSH_G[i].x * basis[i];
        result.b += gSH_B[i].x * basis[i];
    }
    return max(result, 0.0);           // 음수 조명은 물리적으로 없으니 클램프
}

줄 단위 해부

cbuffer ProbeCB : register(b3)는 프로브 계수를 상수 버퍼 슬롯 b3에 바인딩합니다. HLSL cbuffer는 16바이트(float4) 정렬을 강제하므로, 스칼라 9개를 그냥 float gSH_R[9]로 두면 각 원소가 16바이트로 패딩돼 레이아웃이 어긋납니다. 그래서 float4 배열로 잡고 .x만 씁니다 (실무에서는 4계수씩 묶어 낭비를 줄이기도 합니다).

[unroll]은 컴파일러에게 이 9회 루프를 완전히 펼치라는 힌트입니다 — 반복 횟수가 상수라 분기 없이 곱셈-덧셈 27쌍으로 전개되어 GPU에서 훨씬 빠릅니다.

수학: result = Σ ci · Yi(n)은 SH 재구성(reconstruction) 그 자체입니다. 저장된 계수 ci와 법선에서 평가한 기저 Yi(n)의 내적이 곧 "이 법선 방향으로 들어오는 평균 간접광"입니다. 푸리에 급수에서 계수와 기저를 곱해 신호를 복원하는 것과 똑같습니다.

함정 SH 재구성 결과는 음수가 될 수 있습니다(ringing/Gibbs 현상). 그대로 쓰면 검은 얼룩이 생기므로 max(result, 0)로 클램프합니다. 강한 그림자 경계처럼 고주파 성분이 큰 경우 저차 SH로는 표현 한계가 있어 "빛 누수"나 "과도한 부드러움"이 나타납니다.

DirectXMath / C++ 대응 (프로브 베이킹 시 계수 적립)

probe_bake.cppcpp
// 프로브 위치에서 방향 dir로 받은 radiance를 SH 계수에 적립한다.
// 몬테카를로 적분: c_i += L(dir) * Y_i(dir) / pdf,  균일 구면이면 pdf = 1/(4π)
void AccumulateSH(float sh[9], const Vec3& radiance, const Vec3& dir, float weight)
{
    float Y[9];
    EvalSH9(dir, Y);                       // 셰이더와 동일한 기저 공식
    for (int i = 0; i < 9; ++i)
        sh[i] += Y[i] * weight;            // (채널은 바깥에서 radiance별로 분리 처리)
}

베이킹의 Y_i(dir)와 셰이딩의 basis[i]는 같은 공식이어야 합니다 — 한쪽 부호나 상수가 다르면 조명이 뒤집히거나 어긋납니다. XMVector3Dot은 계수와 기저를 한 번에 내적할 때 쓸 수 있고, XMVectorSaturate는 max(·,0)+min(·,1) 클램프에 대응합니다.

3. 프로브 그리드 배치와 삼선형 보간 — 공간을 촘촘히 덮는 법

무엇을 만드나: 프로브 하나로는 방 하나를 못 덮습니다. 그래서 프로브를 3D 격자(grid)로 규칙적으로 배치하고, 동적 물체는 자기를 감싼 8개의 최근접 프로브를 삼선형 보간(trilinear interpolation)으로 섞어 자기 위치의 간접광을 얻습니다. 이것이 언리얼의 Volumetric Lightmap, 유니티의 Light Probe Volume, DDGI의 공통 뼈대입니다. 왜 필요한가: 격자 + 보간은 공간 어디서든 부드럽게 변하는 간접광을 주면서도, 저장은 격자점(프로브)에만 하면 되어 효율적입니다.

기하 직관: 표면 점 P가 놓인 격자 셀(정육면체)의 여덟 꼭짓점이 여덟 프로브입니다. P가 어느 꼭짓점에 가까울수록 그 프로브의 몫이 커지도록, 셀 안에서의 상대 위치 (fx,fy,fz)∈[0,1]³로 가중치를 만들어 여덟 값을 섞습니다 — 1차원 선형 보간을 세 축으로 중첩한 것이 삼선형 보간입니다.

probe_grid_sample.hlslhlsl
// 프로브 격자: gGridMin에서 시작해 gSpacing 간격으로 gGridDim개씩 배치.
// 각 프로브는 27 float(RGB×9 SH)를 구조적 버퍼에 저장.
StructuredBuffer<ProbeSH> gProbes : register(t6);  // 길이 = dimX*dimY*dimZ
cbuffer GridCB : register(b2)
{
    float3 gGridMin;    // 격자 원점(월드)
    float3 gSpacing;    // 축별 프로브 간격
    int3   gGridDim;    // 축별 프로브 개수
};

// 3D 격자 인덱스 → 1D 버퍼 인덱스
int ProbeIndex(int3 c) { return (c.z*gGridDim.y + c.y)*gGridDim.x + c.x; }

// 표면 위치 P·법선 N의 간접광을, 감싼 8개 프로브의 삼선형 보간으로 구한다.
float3 SampleProbeGrid(float3 P, float3 N)
{
    float3 g   = (P - gGridMin) / gSpacing;   // 격자 좌표(실수)
    int3   base = (int3)floor(g);             // 셀의 최소 꼭짓점
    float3 f   = g - (float3)base;            // 셀 안 상대 위치 [0,1]³

    float3 sum = 0;  float wSum = 0;
    [unroll] for (int i = 0; i < 8; ++i)
    {
        int3 off = int3(i&1, (i>>1)&1, (i>>2)&1);   // 여덟 꼭짓점 (0/1)³
        int3 c   = clamp(base + off, 0, gGridDim - 1); // 격자 밖은 가장자리로 클램프

        // 삼선형 가중: 각 축에서 가까운 꼭짓점일수록 큰 몫
        float3 tw = lerp(1.0 - f, f, (float3)off);
        float  w  = tw.x * tw.y * tw.z;

        // (선택) 누수 방지: 프로브→P 방향이 법선과 반대면(벽 뒤) 가중 감소
        float3 dir = normalize(gGridMin + (float3)c*gSpacing - P);
        w *= saturate(dot(N, -dir) + 0.2);

        sum  += SampleProbeSH(gProbes[ProbeIndex(c)], N) * w;
        wSum += w;
    }
    return wSum > 1e-4 ? sum / wSum : 0;
}

줄 단위 해부

(P - gGridMin) / gSpacing는 월드 위치를 격자 칸 단위 실수 좌표로 바꿉니다. floor가 셀의 최소 꼭짓점, 소수부 f가 셀 안 위치입니다. off = int3(i&1, (i>>1)&1, (i>>2)&1)은 i=0..7을 정육면체의 여덟 꼭짓점 (0/1, 0/1, 0/1)로 펼치는 비트 트릭입니다.

삼선형 가중의 핵심: lerp(1-f, f, off)는 그 꼭짓점이 off=0인 축에선 1-f, off=1인 축에선 f를 고릅니다. 세 축 가중을 곱한 w = tw.x·tw.y·tw.z가 그 프로브의 몫이고, 여덟 몫의 합은 항상 1이 됩니다(정규화 전에도). 각 프로브에서 SampleProbeSH(·, N)으로 법선 방향의 SH를 복원해 섞습니다.

함정 — 빛 누수(light leak) 순수 삼선형 보간의 최대 약점은 벽을 뚫는 누수입니다. 밝은 방과 어두운 방 사이 벽에 걸친 표면이, 벽 반대편(밝은 방)의 프로브까지 보간에 끌어들여 어두워야 할 면이 밝아집니다. 위 코드의 dot(N, -dir) 가중은 "표면 뒤쪽에 있는 프로브의 몫을 줄이는" 값싼 완화책이지만 완전하지 않습니다 — 근본 해법은 아래 DDGI의 가시성 저장입니다.

4. DDGI로의 연결 — 프로브가 거리까지 기억하면 누수가 사라진다

DDGI(Dynamic Diffuse Global Illumination, NVIDIA 2019)는 위 프로브 그리드를 두 방향으로 확장해 실시간 GI로 끌어올립니다. 첫째, 각 프로브가 매 프레임 소수의 광선을 레이트레이싱해 irradiance를 갱신합니다(정적 베이킹 → 동적). 둘째, irradiance뿐 아니라 방향별 거리·거리²(가시성)를 작은 옥타헤드럴 맵에 함께 저장합니다.

직관 보간할 때 각 프로브에게 "너와 이 표면 사이에 벽이 있니?"를 물을 수 있게 됩니다. 프로브가 저장한 "그 방향으로 본 평균 거리"보다 표면이 더 멀리 있으면(즉 프로브에서 안 보이면) 그 프로브의 가중을 0에 가깝게 낮춥니다 — 체비셰프 부등식으로 가려질 확률을 추정하는 variance shadow map과 같은 원리입니다. 그래서 벽 반대편 프로브가 자동으로 배제되어 누수가 사라집니다.

즉 3절의 삼선형 가중 w에 가시성 항이 하나 더 곱해지는 것이 DDGI 보간의 실체입니다:

ddgi_visibility_weight.hlslhlsl
// 프로브 i의 삼선형 가중 w에, 체비셰프 가시성 항을 곱한다.
//   probeToP  : 프로브 → 표면 P 방향/거리
//   meanDist, meanDist2 : 그 방향으로 프로브가 저장한 거리·거리²(옥타헤드럴 맵에서 조회)
float VisibilityWeight(float3 probePos, float3 P, float meanDist, float meanDist2)
{
    float  dist = distance(probePos, P);
    if (dist <= meanDist) return 1.0;            // 프로브에서 보이면 완전 신뢰

    float variance = abs(meanDist*meanDist - meanDist2);
    float d = dist - meanDist;
    return variance / (variance + d*d);          // 체비셰프: 가려질수록 0으로
}
// 사용: w *= VisibilityWeight(probePos, P, md, md2);  // 3절의 w에 곱함

결과적으로 DDGI는 정적 베이킹 없이(레벨 로드·라이트 이동에 즉시 반응) 누수까지 억제한 디퓨즈 GI를 줍니다. 대신 프로브당 매 프레임 레이 + 갱신 비용이 들어 하드웨어 RT를 전제로 합니다. UE5의 초기 Lumen 이전 세대, 여러 콘솔 타이틀이 이 구조를 채택했습니다. 간접 스페큘러는 여전히 별도로 — 리플렉션 프로브나 SSR/RT 반사로 — 처리합니다.
