Hardware RTGI

DXR · TraceRay · Denoise

하드웨어 RT (DXR RTGI) — 한 줄 한 줄 직접 구현

앞의 SSGI는 화면에 보이는 픽셀만 반사광으로 쓸 수 있었습니다. 하드웨어 레이 트레이싱(DXR)은 그 한계를 정면 돌파합니다 — 각 픽셀에서 진짜 광선을 반구로 쏴 실제 씬 지오메트리와 교차시키므로, 화면 밖·가려진 표면의 간접광까지 물리적으로 정확합니다. 대가는 노이즈입니다. 픽셀당 광선이 적어 결과가 지글거리고, 그래서 디노이저가 필수 짝입니다. 이 페이지는 픽셀마다 광선을 만들고 쏘는 ray generation 셰이더를 한 줄씩 해부하고, 아래 데모로 "광선 수 ↑ = 노이즈 ↓", "디노이즈로 매끈하게"를 직접 만져 봅니다.

규약 — 이 페이지만 D3D12/DXR 앞의 라이트맵·프로브·SSGI·VXGI는 Direct3D 11 기반이지만, DXR은 Direct3D 12 전용입니다. 별도의 RT 파이프라인 상태 객체와 SBT(Shader Binding Table) 구성이 필요합니다. 벡터·행렬 규약(행벡터 v' = v*M, 왼손 좌표계, 클립 z ∈ [0,1])은 사이트 공통을 그대로 따릅니다. 코드는 원리 학습용 최소 형태입니다.

직관 데모 — 광선이 적으면 노이즈, 디노이저가 매끈하게

아래는 프래그먼트 셰이더에서 도는 작은 실시간 레이트레이서입니다. 바닥과 구가 있고, 좌우 색벽이 간접광을 물들입니다(color bleeding). 화면 왼쪽 절반은 픽셀당 광선(spp)만큼만 반구를 샘플한 raw 결과라 지글거리고, 오른쪽 절반은 같은 장면을 디노이즈한 결과입니다. spp를 올리면 raw 쪽도 깨끗해지고, 디노이즈를 올리면 오른쪽이 매끈해집니다 — 실무 RTGI가 "적은 광선 + 강한 디노이저"로 가는 이유를 눈으로 확인하세요.

렌더링…

가운데 초록 선 = 좌(raw) / 우(디노이즈) 경계. 좌측이 지글거리는 게 몬테카를로 노이즈이고, spp를 올리면 1/√N로 줄어듭니다. 값은 개념 이해용 근사입니다.

하드웨어 RT (DXR) — RT 코어로 소수 광선을 실시간 추적

무엇을 만드나: DirectX Raytracing(DXR)의 RT 코어를 이용해, 각 픽셀에서 진짜 광선 하나를 반구로 쏴 실제 씬과 교차시키고 1바운스 간접광을 얻습니다. 화면 밖·가려진 정보까지 정확하다는 점이 SSGI와의 결정적 차이입니다. 왜 필요한가: 근사가 아닌 실제 가시성 기반 GI라서 반사·그림자와 물리적으로 일관됩니다. 대신 픽셀당 광선 수가 적어 노이즈가 크고, 디노이저가 필수입니다.

DXR은 ray generation → traversal → hit/miss 셰이더로 나뉩니다. 아래는 픽셀마다 광선을 만들고 쏘는 ray generation 셰이더입니다.

rtgi_raygen.hlslhlsl
RaytracingAccelerationStructure gScene : register(t0);  // TLAS(가속 구조)
RWTexture2D<float4>             gOutput : register(u0);  // GI 결과 출력(UAV)
Texture2D<float4>              gGBufPos : register(t1);  // 픽셀별 월드 위치
Texture2D<float4>              gGBufNrm : register(t2);  // 픽셀별 월드 법선

struct Payload { float3 color; };   // 히트/미스 셰이더가 채워 돌려줄 데이터

[shader("raygeneration")]
void RayGen()
{
    uint2 px = DispatchRaysIndex().xy;          // 현재 픽셀 좌표
    float3 P = gGBufPos[px].xyz;                // 이 픽셀의 표면 위치
    float3 N = normalize(gGBufNrm[px].xyz);     // 표면 법선

    float3 dir = CosineHemisphere(px, N);       // 코사인 가중 반구 방향 1개

    RayDesc ray;
    ray.Origin    = P + N * 1e-3;               // self-hit 방지용 오프셋
    ray.Direction = dir;
    ray.TMin      = 0.0;
    ray.TMax      = 1e30;                        // 사실상 무한대

    Payload pl = { float3(0, 0, 0) };
    TraceRay(gScene,
             RAY_FLAG_NONE,
             0xFF,          // instance mask: 모든 인스턴스와 교차
             0, 0, 0,       // hit group / miss shader 인덱스
             ray, pl);

    gOutput[px] = float4(pl.color, 1.0);        // 1바운스 간접광 기록
}

DXR 자원·문법 해부

RaytracingAccelerationStructure gScene는 씬 지오메트리를 광선 교차에 최적화된 트리로 담은 가속 구조(TLAS/BLAS)입니다 — C++에서 BuildRaytracingAccelerationStructure로 미리 만듭니다. RWTexture2D<float4>는 셰이더가 쓸 수 있는 텍스처(UAV, slot u0)로, GI 결과를 여기에 기록합니다. <float4>는 원소 타입 지정(제네릭 문법)입니다.

[shader("raygeneration")] 어트리뷰트는 이 함수가 ray generation 진입점임을 런타임에 알립니다. DispatchRaysIndex().xy는 DispatchRays(width, height, 1)로 뿌린 격자에서 이 스레드가 담당하는 픽셀을 줍니다(컴퓨트 셰이더의 SV_DispatchThreadID와 유사).

RayDesc·TraceRay 매핑

RayDesc는 광선 하나의 명세입니다: Origin(시작점), Direction(방향), TMin/TMax(유효 거리 구간). TMax = 1e30은 "얼마든 멀리까지"라는 뜻이고, TMin = 0이라도 Origin을 법선으로 1e-3 띄워 self-hit(라이트맵 절과 동일한 함정)을 막습니다.

TraceRay가 실제로 RT 코어를 돌립니다. 인자 0xFF는 인스턴스 마스크(모든 물체와 교차 허용), 그다음 세 0은 hit group·miss shader·SBT 오프셋 인덱스입니다. 광선이 무언가에 맞으면 closest-hit 셰이더가, 아무것도 못 맞으면 miss 셰이더가 pl.color를 채워 돌려줍니다 — 그 값을 gOutput에 씁니다.

함정 Payload 크기는 작게 유지해야 합니다 — 모든 재귀 광선이 이 구조체를 들고 다녀 크면 레지스터 압박과 성능 저하를 부릅니다. 또 픽셀당 광선 1개라 결과는 매우 노이즈합니다. 그대로 화면에 쓰면 지글거리므로 반드시 시공간 디노이저 (예: SVGF, ReSTIR)를 뒤에 붙여야 실사용 가능합니다.
성능 RTGI 비용은 픽셀 수 × 픽셀당 광선 × 광선당 순회·셰이딩입니다. 1080p·픽셀당 1광선이면 프레임당 약 200만 광선이고, 바운스를 늘리면 배가됩니다. 그래서 실무는 광선 수를 극도로 아끼고(픽셀당 1개 이하 + 시간적 누적/ReSTIR), 디노이저와 업스케일러(DLSS/FSR)로 최종 품질을 확보합니다.

C++/D3D12 대응

gScene는 ID3D12Device5::CreateStateObject로 만든 RT 파이프라인과 가속 구조 SRV로 바인딩하고, TraceRay를 유발하는 디스패치는 CPU에서 ID3D12GraphicsCommandList4::DispatchRays로 호출합니다. DispatchRaysIndex의 격자는 이 DispatchRays의 Width/Height/Depth에 대응합니다. DXR은 D3D12 전용이라, D3D11 기반의 앞 절들과 달리 별도 파이프라인·SBT(Shader Binding Table) 구성이 필요합니다.

이웃 기법 연결 RTGI는 SSGI의 화면 밖 한계를 없앤 상위 호환이지만 비쌉니다. 그래서 실무는 SSGI/SSR을 먼저 시도 → 실패 픽셀만 RT로 폴백하는 하이브리드를 씁니다. 간접 디퓨즈를 프로브에 실시간 누적하는 DDGI도 RT를 전제로 하고, 간접 스페큘러는 리플렉션 프로브·RT 반사가 맡습니다.
