전역 조명 (Global Illumination) — 기법별 직접 구현

전역 조명(GI)은 빛이 표면끼리 여러 번 튕기며 만드는 간접광입니다. 앞 절의 패스 트레이서는 이미 완전한 GI를 계산합니다 — 재귀 바운스가 곧 간접광이고, 빨간 벽 옆 흰 구가 붉게 물드는 color bleeding이 그 증거입니다. 즉 정답은 이미 있습니다. 문제는 실시간이라는 제약입니다. 이 챕터는 실시간에서 GI를 "충분히 그럴싸하게" 근사하는 다섯 기법을 각각 비주얼 데모로 먼저 감을 잡고, 개념 → 수식 → 기하 직관 → HLSL/C++ 코드 한 줄까지 해부하는 세부 페이지로 나눠 다룹니다. 아래 카드에서 원하는 기법으로 바로 들어가세요.

규약 이 챕터의 모든 코드는 행벡터 규약(v' = v * M, HLSL mul(v, M)), 행 우선 저장, 왼손 좌표계, 클립 공간 z ∈ [0,1], 텍스처 V축 위→아래를 따릅니다. 실무에서는 DirectXMath와 검증된 라이브러리 사용을 권장하며, 코드는 원리 학습용으로 최소 형태만 남겼습니다.

0. 큰 그림 — 왜 근사가 필요한가

물리적으로 정확한 조명은 렌더링 방정식(Kajiya, 1986) 하나로 요약됩니다. 어떤 점 x에서 방향 ωo로 나가는 빛 Lo는 그 점이 스스로 내는 빛 Le에, 반구 전체에서 들어오는 모든 빛을 BRDF로 가중해 적분한 값을 더한 것입니다:

Lo(x, ωo) = Le + ∫Ω fr(x, ωi, ωo) · Li(x, ωi) · (n·ωi) dωi

여기서 핵심은 Li(들어오는 빛) 안에 다른 표면에서 나간 빛이 들어있다는 점입니다. 즉 이 방정식은 자기 자신을 재귀적으로 참조합니다 — 빛이 A에서 B로, B에서 C로 무한히 튕기는 것이 곧 이 재귀입니다. 패스 트레이싱은 이 적분을 몬테카를로 샘플링으로 직접 푸는 것이고, 정답이지만 느립니다.

실시간 기법들은 모두 이 적분을 어딘가에서 잘라내는(근사하는) 전략의 차이입니다:

기법아이디어장점한계
라이트맵 (베이킹) 오프라인에서 GI를 계산해 텍스처에 굽는다 런타임 비용 거의 0, 품질 최고 정적 씬 전용, 굽는 시간 김
Irradiance Probes 공간에 프로브를 배치해 방향별 간접광 저장, 동적 물체가 보간해 샘플 동적 물체 대응, 비교적 저렴 프로브 밀도·배치에 품질 의존, 누수(light leak)
SSGI SSAO처럼 화면 공간에서 간접 반사광을 근사 저렴, 기존 G-buffer 재사용 화면 밖 정보는 못 씀(SSR과 같은 한계)
Voxel GI (VXGI) 씬을 복셀화해 원뿔 추적(cone tracing)으로 간접광 근사 완전 동적 GI 가능 메모리·성능 부담, 복셀 해상도 한계
하드웨어 RT / RTGI RT 코어로 소수 광선을 실시간 추적 + 강력한 디노이징 (DXR / DirectX Raytracing) 동적·정확, 반사/그림자 통합 고성능 GPU 필요, 여전히 노이즈/시간적 안정성 과제
주의 최신 흐름은 하이브리드입니다: 래스터화로 기본 화면을 그리고(빠름), 반사·그림자·GI 일부만 하드웨어 RT로 소량 추적한 뒤 시공간(spatio-temporal) 디노이저로 다듬습니다. UE5의 Lumen이 대표적으로 SDF/화면공간 추적과 하드웨어 RT를 상황에 따라 섞습니다.
범위 정리 — 이 챕터는 간접 디퓨즈 GI를 실무에서는 흔히 간접 디퓨즈(부드럽게 번지는 색·color bleeding)와 간접 스페큘러(환경 반사·거울상)로 나눠 다룹니다. 이 챕터는 라이트맵·프로브·SSGI·VXGI·RTGI로 간접 디퓨즈를 근사하는 데 초점을 둡니다. 간접 스페큘러의 정석 — 환경맵을 irradiance·프리필터·split-sum BRDF LUT로 굽고 리플렉션 프로브로 배치하는 파이프라인 — 은 이미지 기반 조명(IBL) · 리플렉션 프로브에서 한 줄씩 구현합니다. 아래 프로브 페이지의 SH 프로브는 그 IBL 페이지의 디퓨즈 대응편입니다.

기법별로 들어가기 — 각 페이지에 비주얼 데모 + 직접 구현

다섯 기법을 런타임 비용이 낮은 순(정적 → 동적)으로 배치했습니다. 각 페이지는 만지는 데모로 감을 잡은 뒤 코드를 한 줄씩 해부합니다.
