Image-Based Lighting

Irradiance · Prefilter · Split-Sum · Reflection Probe

이미지 기반 조명 (IBL) · 리플렉션 프로브 — 한 줄 한 줄 직접 구현

PBR 페이지의 마지막에서, 우리는 점광원 몇 개만으로는 진짜 재질감이 안 나온다는 것을 봤습니다. 금속 구가 사실적이려면 주변 환경 전체가 그 표면에 비쳐야 하기 때문입니다. 이미지 기반 조명(Image-Based Lighting, IBL)은 바로 이 "환경 전체를 광원으로 쓰는" 기법입니다 — 하늘·벽·바닥이 담긴 환경맵(큐브맵)을 하나의 거대한 면광원으로 취급합니다. 문제는 반사 방정식의 반구 적분을 픽셀마다 다시 풀 수 없다는 것. 그래서 IBL은 이 적분을 미리(오프라인) 굽고, 런타임에는 텍스처를 몇 번 샘플만 합니다. 이 페이지에서는 그 세 조각 — 디퓨즈 irradiance 큐브맵 · 스페큘러 프리필터 큐브맵 · split-sum BRDF LUT — 을 굽는 셰이더를 한 줄씩 해부하고, 이 환경맵을 씬 곳곳에 배치하는 리플렉션 프로브까지 만들어 봅니다. (개념·직관 먼저 잡고 싶다면 → 개념 트랙: 이미지 기반 조명)

규약 이 페이지의 모든 코드는 사이트 공통 규약을 따릅니다: 행벡터 v' = v * M(HLSL mul(v, M)), 행 우선 저장, 왼손 좌표계, 클립 z ∈ [0,1], 텍스처 V축 위→아래. 조명은 선형 공간(linear)에서 계산하며, 환경맵은 반드시 HDR(부동소수 큐브맵)이어야 합니다 — 하이라이트가 1을 넘는 값을 담아야 프리필터가 물리적으로 맞습니다. 코드는 검증된 라이브러리 대신 원리 학습용으로 최소 형태만 남겼습니다.

0. 큰 그림 — 환경을 광원으로, 그리고 split-sum 근사

IBL이 풀려는 것은 PBR과 똑같은 반사 방정식입니다. 다만 입사광 Li가 몇 개의 점광원이 아니라 환경맵의 모든 방향이라는 점만 다릅니다:

Lo(v) = ∫Ω f(l, v) · Lenv(l) · (n·l) dl

Cook-Torrance BRDF f는 디퓨즈 항과 스페큘러 항의 합이므로, 이 적분도 자연스럽게 둘로 갈라집니다. 디퓨즈 쪽은 BRDF가 방향에 둔감(람베르트)해서 법선 방향 하나로 결과가 정해집니다 — 그래서 "법선 → 색" 큐브맵 한 장(irradiance map)으로 미리 구울 수 있습니다. 스페큘러 쪽이 골칫거리입니다: BRDF가 보는 방향·거칠기·프레넬에 모두 얽혀 있어 4차원 적분이라 통째로 굽지 못합니다.

직관 Epic Games(Karis, 2013)의 split-sum 근사는 이 얽힌 스페큘러 적분을 두 개의 독립된 평균의 곱으로 쪼갭니다: ① "이 거칠기에서 환경은 평균적으로 어떤 색으로 뭉개져 보이나"(= 거칠기별로 흐려진 환경 = 프리필터 큐브맵)와, ② "그 반사가 프레넬·기하 손실로 얼마나 세게/약하게 나오나"(환경과 무관한 순수 BRDF 적분 = BRDF LUT). 환경에만 의존하는 항과 BRDF에만 의존하는 항으로 분리했기에, 둘 다 오프라인에서 미리 구울 수 있게 됩니다.

∫ f·L·(n·l) dl ≈ (∫ Lenv·(n·l) dl / ∫(n·l) dl) × (∫ f·(n·l) dl)
└─ 프리필터 큐브맵(환경만) ─┘   └─ BRDF LUT(BRDF만) ─┘

정리하면 IBL은 아래 세 개의 미리 구운 텍스처로 앰비언트를 대체합니다. 이 페이지는 각 줄을 실제로 굽습니다:

미리 굽는 것무엇을 담나인덱스(런타임 조회 키)해상도 감각
Irradiance 큐브맵
(디퓨즈)		 법선 방향으로 들어오는 코사인 가중 평균 간접광 표면 법선 n 아주 작아도 됨(예: 32²×6) — 저주파라 뭉툭
프리필터 큐브맵
(스페큘러 ①)		 거칠기별로 흐려진 환경 — 밉 레벨 = 거칠기 반사 벡터 r + 거칠기(밉) 128²×6 + 밉 체인(거칠기 5~6단계)
BRDF LUT
(스페큘러 ②)		 프레넬·기하 항의 적분 결과(scale, bias) (n·v, 거칠기) 2D 512² 2채널(RG16F), 씬과 무관해 한 번만
함정 IBL은 무한히 먼 환경을 가정합니다 — 큐브맵은 방향만 알 뿐 거리가 없어서, 방 안 어디서 봐도 벽이 같은 방향에 있다고 착각합니다. 그래서 하나의 큐브맵으로 실내 전체를 덮으면 반사가 어긋납니다. 이 한계를 푸는 것이 아래 리플렉션 프로브의 parallax correction(위치 보정)입니다.

직관 데모 — 거칠기가 곧 밉 레벨이다

split-sum의 핵심 직관을 손으로 만져 봅시다. 아래 구는 절차적 환경(하늘·태양·바닥)에 놓여 있습니다. 거칠기를 올리면 반사가 흐려지는데, 이것은 프리필터 큐브맵의 더 높은 밉 레벨을 읽는 것과 정확히 같습니다 — 거친 표면일수록 넓은 각도의 환경을 평균해 보기 때문입니다. metallic을 내리면 디퓨즈 irradiance(뭉툭한 평균광)의 비중이 커지고, 올리면 순수 환경 반사가 지배합니다. 오른쪽 HUD가 지금 어느 밉을 읽는지 보여줍니다.

렌더링…

왼쪽 = IBL로 조명한 구, 오른쪽 위 = 지금 읽는 프리필터 밉(거칠기로 선택), 오른쪽 아래 = irradiance(디퓨즈, 항상 최대로 뭉갬). 거칠기 0 = 밉 0(거울), 거칠기 1 = 최상위 밉(완전 확산)입니다. 값은 개념 이해용 근사입니다.

1. 디퓨즈 Irradiance 큐브맵 — 반구를 컨볼루션해 굽는다

무엇을 만드나: 환경맵의 각 방향(=출력 큐브맵의 텍셀)에 대해, 그 방향을 법선으로 놓은 반구 전체를 훑어 코사인 가중 평균을 낸 큐브맵입니다. 런타임 셰이더는 표면 법선으로 이 큐브맵을 단 한 번 샘플해 디퓨즈 간접광을 얻습니다. 왜 필요한가: 디퓨즈는 저주파(뭉툭)라 이렇게 미리 뭉개도 손실이 거의 없고, 픽셀당 반구 적분을 텍스처 읽기 하나로 바꿔 줍니다.

수식 디퓨즈 irradiance는 E(n) = ∫Ω Lenv(l) · (n·l) dl 입니다. 여기에 람베르트 BRDF albedo/π를 곱하면 최종 디퓨즈가 되지만, BRDF의 albedo는 런타임 재질값이므로 큐브맵에는 순수 E(n)만 굽고 albedo는 셰이딩 때 곱합니다.

1-1. 반구 컨볼루션 셰이더 (HLSL)

출력 큐브맵의 한 텍셀을 그리는 픽셀 셰이더입니다. 그 텍셀의 월드 방향을 법선 N으로 삼고, 접선 공간에서 반구를 촘촘히 돌며 환경맵을 적분합니다. 큐브맵 6면을 렌더 타깃으로 한 면씩 그리며 이 셰이더가 호출됩니다.

irradiance_convolve.hlslhlsl
TextureCube  gEnv  : register(t0);   // 원본 HDR 환경 큐브맵
SamplerState gSamp : register(s0);

// 이 텍셀이 대표하는 반구의 축(월드 방향). VS가 큐브 면 위치로 만들어 넘겨줌.
float4 main(float3 worldDir : DIRECTION) : SV_Target
{
    float3 N = normalize(worldDir);      // 반구의 축 = 이 텍셀의 법선

    // N을 축으로 하는 접선 기저(up이 N과 나란하면 축을 바꿔 특이점 회피)
    float3 up      = abs(N.y) < 0.999 ? float3(0,1,0) : float3(0,0,1);
    float3 tangent = normalize(cross(up, N));
    float3 bitan   = cross(N, tangent);

    float3 irradiance = 0;
    float  nrSamples  = 0.0;
    const float TWO_PI = 6.2831853;
    const float HALF_PI = 1.5707963;

    // 방위각 phi(0..2π) × 극각 theta(0..π/2)를 균일 각도 간격으로 훑는다.
    for (float phi = 0.0; phi < TWO_PI; phi += 0.025)
    for (float theta = 0.0; theta < HALF_PI; theta += 0.025)
    {
        // 접선 공간 방향(구면좌표) → 월드 방향
        float3 tanSample = float3(sin(theta)*cos(phi), sin(theta)*sin(phi), cos(theta));
        float3 L = tanSample.x*tangent + tanSample.y*bitan + tanSample.z*N;

        // 코사인(cosθ) · 입체각 보정(sinθ) 가중으로 환경을 적립
        irradiance += gEnv.Sample(gSamp, L).rgb * cos(theta) * sin(theta);
        nrSamples  += 1.0;
    }
    // π·(합/표본수): 균일 각도 샘플의 정규화 상수
    irradiance = 3.14159265 * irradiance * (1.0 / nrSamples);
    return float4(irradiance, 1.0);
}

줄 단위 해부

TextureCube gEnv는 6면을 하나로 묶은 큐브맵 타입입니다. Sample(samp, dir)에 UV가 아니라 방향 벡터를 넣으면 하드웨어가 어느 면의 어느 텍셀인지 알아서 골라 줍니다 — 큐브맵의 핵심 편의입니다.

up = abs(N.y) < 0.999 ? (0,1,0) : (0,0,1)은 접선 기저를 만들 때 특이점(gimbal)을 피합니다. 법선이 정확히 위/아래를 가리키면 cross(up, N)이 0이 되어 기저가 무너지므로, 그 경우만 보조축을 바꿉니다.

수학 → 코드: cos(theta)는 반사 방정식의 (n·l) 코사인 항이고, sin(theta)는 구면좌표에서 극각 theta 근처 띠의 실제 입체각(dl = sinθ dθ dφ)을 보정합니다. 이 둘을 곱해 적립하고, 마지막 π · 합/N이 균일 각도 샘플링의 정규화 상수입니다. 결과가 곧 E(N)입니다.

성능 이 이중 루프는 텍셀당 약 (2π/0.025)×(π/2·1/0.025) ≈ 250×63 ≈ 1.6만 샘플입니다. 하지만 irradiance 큐브맵은 32²×6처럼 작아도 충분하고(저주파), 씬당 한 번만 굽습니다(정적 환경). 동적 하늘이면 매 프레임 다시 굽는 대신 구면 조화(SH)로 압축해 9계수만 갱신하는 편이 훨씬 쌉니다 — 그 SH 경로는 전역 조명: Irradiance Probe에서 다룹니다.

2. 스페큘러 프리필터 큐브맵 — 거칠기를 밉 레벨에 굽는다

무엇을 만드나: 같은 환경맵을 거칠기 단계별로 흐리게 만들어 밉 체인에 저장합니다. 밉 0 = 원본(거울), 밉이 올라갈수록 더 거친 표면용으로 넓게 뭉갠 버전입니다. 런타임에는 반사 벡터 R로 샘플하되, 밉 레벨을 roughness로 지정합니다. 왜 필요한가: split-sum의 ① 항(환경 부분)을 이 한 장으로 끝냅니다 — "이 거칠기에서 환경이 평균 무슨 색인가"가 미리 구워져 있습니다.

직관 거친 금속의 흐릿한 반사는 수많은 미세면이 조금씩 다른 방향을 반사한 것의 평균입니다. 그 평균을 픽셀마다 다시 구하는 대신, GGX 분포(D)를 중요도 샘플링해 반사 방향 주변을 가중 평균한 결과를 밉에 미리 구워 둡니다.
prefilter_env.hlslhlsl
TextureCube  gEnv  : register(t0);
SamplerState gSamp : register(s0);
cbuffer PrefilterCB : register(b0) { float gRoughness; };  // 이 밉이 대표하는 거칠기

// GGX 중요도 샘플: (u1,u2) 난수 → 거칠기 a에서 있음직한 하프벡터 방향
float3 ImportanceSampleGGX(float2 Xi, float3 N, float a)
{
    float phi      = 6.2831853 * Xi.x;
    float cosTheta = sqrt((1.0 - Xi.y) / (1.0 + (a*a - 1.0) * Xi.y));
    float sinTheta = sqrt(1.0 - cosTheta*cosTheta);

    float3 H = float3(sinTheta*cos(phi), sinTheta*sin(phi), cosTheta); // 접선 공간
    float3 up      = abs(N.z) < 0.999 ? float3(0,0,1) : float3(1,0,0);
    float3 tangent = normalize(cross(up, N));
    float3 bitan   = cross(N, tangent);
    return normalize(tangent*H.x + bitan*H.y + N*H.z);                 // 월드로
}

float4 main(float3 worldDir : DIRECTION) : SV_Target
{
    float3 N = normalize(worldDir);
    float3 R = N;  float3 V = N;     // 근사: 보는 방향 = 반사 방향 = N (Karis 가정)

    const uint SAMPLES = 1024;
    float3 prefiltered = 0;
    float  totalWeight = 0.0;

    for (uint i = 0; i < SAMPLES; ++i)
    {
        float2 Xi = Hammersley(i, SAMPLES);            // 저불일치 2D 난수
        float3 H  = ImportanceSampleGGX(Xi, N, gRoughness);
        float3 L  = reflect(-V, H);                    // V를 H로 반사 → 입사 방향

        float NoL = max(dot(N, L), 0.0);
        if (NoL > 0.0)
        {
            prefiltered += gEnv.Sample(gSamp, L).rgb * NoL;  // NoL 가중 평균
            totalWeight += NoL;
        }
    }
    return float4(prefiltered / totalWeight, 1.0);
}

수학 → 기하 직관 → 코드 매핑

ImportanceSampleGGX는 균일 난수 (Xi.x, Xi.y)를 GGX 분포가 큰 방향으로 변환합니다. cosTheta 공식은 GGX의 누적분포를 역함수로 뒤집은 것으로, 거칠기 a가 작으면 하프벡터가 N 주변에 몰리고(좁은 하이라이트), 크면 넓게 퍼집니다. 그래서 기여가 큰 방향에만 표본을 집중해 적은 샘플로도 매끈한 결과를 얻습니다.

R = V = N은 Karis의 핵심 근사입니다 — 프리필터를 구울 때는 보는 각도 정보가 없으므로 "정면에서 본다"고 가정합니다. 그래서 스치는 각의 길쭉한 반사(anisotropic streak)는 표현 못 하지만, 이 덕분에 큐브맵 한 장으로 모든 시선각을 커버합니다.

reflect(-V, H)는 시선 V를 미세면 법선 H에 대해 반사해 그 미세면이 어느 환경 방향을 비추는지(L)를 구합니다. NoL 가중은 표면에 스치듯 들어오는 방향의 기여를 줄여, 결과가 물리적으로 편향되지 않게 합니다.

함정 각 밉 레벨을 그릴 때 gRoughness를 그 밉에 맞는 값(예: mip / (mipCount-1))으로 넘겨야 합니다. 또 밉 0(거칠기 0)은 적분이 델타 함수라 원본을 그대로 복사하는 게 정확합니다. 밉 선택 시 큐브맵 seam(면 경계)에서 필터가 튀지 않도록 D3D11_TEXCUBE 생성 시 MiscFlags에 D3D11_RESOURCE_MISC_TEXTURECUBE와 밉 생성 옵션을 함께 켜야 합니다.

3. BRDF LUT — split-sum의 둘째 항(BRDF만)을 2D 텍스처로

무엇을 만드나: 환경과 무관한 순수 BRDF 적분을 (n·v, 거칠기) 축의 2D 텍스처에 굽습니다. 각 텍셀은 두 값(scale, bias)을 담아 프레넬 F0에 F0·scale + bias로 적용됩니다. 왜 필요한가: 이 항은 씬·환경이 무엇이든 바뀌지 않으므로 앱 전체에서 딱 한 번 굽고 재사용합니다.

brdf_lut.hlslhlsl
// 출력: RG16F. R = 프레넬 scale, G = 프레넬 bias.
float2 IntegrateBRDF(float NoV, float roughness)
{
    // 시선 V를 (NoV로부터) 접선 공간에 복원. N = (0,0,1)로 고정.
    float3 V = float3(sqrt(1.0 - NoV*NoV), 0.0, NoV);
    float3 N = float3(0, 0, 1);

    float A = 0.0, B = 0.0;
    const uint SAMPLES = 1024;
    for (uint i = 0; i < SAMPLES; ++i)
    {
        float2 Xi = Hammersley(i, SAMPLES);
        float3 H  = ImportanceSampleGGX(Xi, N, roughness);
        float3 L  = reflect(-V, H);

        float NoL = max(L.z, 0.0);
        float NoH = max(H.z, 0.0);
        float VoH = max(dot(V, H), 0.0);
        if (NoL > 0.0)
        {
            float G     = GeometrySmithIBL(N, V, L, roughness); // IBL용 k=a²/2
            float G_Vis = (G * VoH) / (NoH * NoV);
            float Fc    = pow(1.0 - VoH, 5.0);                  // 프레넬의 (1-VoH)^5 부분
            A += (1.0 - Fc) * G_Vis;                            // scale
            B += Fc * G_Vis;                                    // bias
        }
    }
    return float2(A, B) / SAMPLES;
}

왜 scale·bias 두 값인가: 프레넬-슐릭은 F = F0 + (1-F0)(1-VoH)⁵입니다. 적분 안에서 F0을 밖으로 빼면 F0·∫(1-Fc)G' + ∫Fc·G' 꼴로 정확히 두 항으로 분리됩니다 — 앞이 A(scale), 뒤가 B(bias)입니다. 그래서 런타임에는 재질의 F0만 알면 F0·A + B로 프레넬·기하 적분 결과를 테이블 조회 한 번으로 복원합니다.

함정 BRDF LUT는 클램프 샘플러(ADDRESS_CLAMP)로 읽어야 합니다 — 가장자리(NoV→0 또는 거칠기 0/1)에서 wrap되면 반대편 값이 새어 프레넬이 폭발합니다. 또 IBL의 기하 항 G는 직접광과 k가 다릅니다(k = a²/2 vs 직접광 (a+1)²/8). 이 둘을 섞으면 거친 재질의 밝기가 어긋납니다.

4. 세 조각을 합쳐 앰비언트를 대체 (런타임 셰이딩)

이제 굽는 건 끝났습니다. 런타임 PBR 픽셀 셰이더에서 PBR 페이지의 밋밋한 앰비언트 albedo * 0.03을 아래 IBL 블록으로 갈아끼우면, 추가 광원 없이도 환경이 재질에 사실적으로 비칩니다.

ibl_shading.hlsl (PBR 픽셀 셰이더 일부)hlsl
TextureCube  gIrradiance : register(t3);  // 1절에서 구운 것
TextureCube  gPrefilter  : register(t4);  // 2절 (밉 체인 있음)
Texture2D    gBRDFLut    : register(t5);  // 3절
SamplerState gSamp       : register(s0);

float3 ComputeIBL(float3 N, float3 V, float3 albedo, float metallic, float roughness)
{
    float3 F0 = lerp(0.04, albedo, metallic);      // 비금속 0.04, 금속=albedo
    float  NoV = max(dot(N, V), 0.0);

    // 스치는 각까지 고려한 프레넬(거칠기 반영 roughness-aware Fresnel)
    float3 F  = F0 + (max(1.0 - roughness, F0) - F0) * pow(1.0 - NoV, 5.0);
    float3 kd = (1.0 - F) * (1.0 - metallic);      // 디퓨즈 몫(에너지 보존)

    // --- 디퓨즈: irradiance 한 번 샘플 ---
    float3 irradiance = gIrradiance.Sample(gSamp, N).rgb;
    float3 diffuse    = irradiance * albedo;

    // --- 스페큘러: 프리필터(밉=거칠기) × BRDF LUT ---
    float3 R = reflect(-V, N);
    const float MAX_MIP = 5.0;
    float3 prefiltered = gPrefilter.SampleLevel(gSamp, R, roughness * MAX_MIP).rgb;
    float2 brdf        = gBRDFLut.Sample(gSamp, float2(NoV, roughness)).rg;
    float3 specular    = prefiltered * (F * brdf.x + brdf.y);   // split-sum 합성

    return kd * diffuse + specular;   // (선택) × ambientOcclusion
}

마지막 줄이 이 페이지 전체의 결론입니다: 디퓨즈(irradiance×albedo) + 스페큘러(prefiltered × (F·scale + bias)). 환경 반구 적분이 텍스처 세 번 샘플로 줄었습니다. SampleLevel(..., roughness*MAX_MIP)이 데모에서 만졌던 "거칠기 = 밉" 그 자체입니다.

5. 리플렉션 프로브 — 환경맵을 씬에 배치하다

지금까지의 환경맵은 하나의 무한히 먼 하늘이었습니다. 하지만 실내를 걸으면 방마다·구석마다 비치는 환경이 다릅니다. 리플렉션 프로브(reflection probe)는 씬의 특정 위치에 카메라를 놓고 그 지점에서 본 환경을 큐브맵으로 캡쳐해, 그 큐브맵으로 위 IBL 파이프라인(프리필터·BRDF LUT)을 그대로 돌립니다. 언리얼의 리플렉션 캡쳐(Reflection Capture)가 사실상 같은 개념입니다.

  1. 프로브 위치에 6방향 카메라를 놓고 씬을 렌더 → 로컬 HDR 큐브맵 캡쳐(정적이면 에디터에서 한 번, 동적이면 주기적 갱신).
  2. 그 큐브맵을 1~3절 파이프라인으로 프리필터·irradiance로 굽는다(프로브마다).
  3. 런타임에 표면은 가장 가까운/영향 반경 안의 프로브들을 골라 샘플하고, 경계에서 블렌딩한다.
  4. 먼 환경 가정이 깨지지 않도록 parallax correction으로 반사 벡터를 프로브의 경계 볼륨에 맞춰 보정한다.

5-1. Parallax correction — 무한 환경 가정을 고치는 한 단락

문제: 순수 큐브맵 샘플 gCube.Sample(s, R)은 반사 벡터의 방향만 씁니다. 그래서 방 한쪽 끝에서 보나 반대쪽에서 보나 같은 벽면이 같은 방향에 있다고 착각해, 반사가 표면에 "붙어" 미끄러집니다. 해결: 프로브에 경계 상자(또는 구)를 주고, 반사 광선이 그 상자와 실제로 만나는 지점을 구해, 프로브 중심에서 그 교차점으로 향하는 보정된 방향으로 큐브맵을 샘플합니다.

parallax_box.hlslhlsl
// 박스 parallax correction: 반사 벡터 R을 프로브 경계 상자에 맞춰 보정한다.
//   worldPos  : 셰이딩 중인 표면 위치
//   R         : 원래 반사 벡터(normalize된 방향)
//   boxMin/Max: 프로브 경계 상자(AABB, 월드)
//   probePos  : 프로브(큐브맵 캡쳐) 중심 위치
float3 ParallaxCorrectR(float3 worldPos, float3 R, float3 boxMin, float3 boxMax, float3 probePos)
{
    // 광선 worldPos + t·R 이 상자 여섯 평면과 만나는 t들 중, 앞쪽(양수) 최소 교차
    float3 firstPlane  = (boxMax - worldPos) / R;   // 성분별: 각 축 상한면까지의 t
    float3 secondPlane = (boxMin - worldPos) / R;   // 각 축 하한면까지의 t
    float3 furthest    = max(firstPlane, secondPlane);      // 각 축에서 나가는 t
    float  t           = min(min(furthest.x, furthest.y), furthest.z); // 상자를 빠져나가는 지점

    float3 hitPos = worldPos + R * t;               // 반사가 실제로 닿는 상자 위 점
    return hitPos - probePos;                        // 프로브 중심 → 그 점 = 보정 방향
}
// 사용: float3 Rc = ParallaxCorrectR(P, reflect(-V,N), bMin, bMax, probePos);
//       float3 env = gPrefilter.SampleLevel(gSamp, Rc, roughness*MAX_MIP).rgb;

기하 직관 — 왜 이 몇 줄이 반사를 "고정"하나

수학: (boxMax - worldPos)/R는 광선 P + tR이 각 축의 상한 평면과 만나는 매개변수 t를 성분별로 준 것입니다. 각 축마다 상·하한 중 나가는 쪽(max)을 고르고, 세 축 중 가장 먼저 상자를 벗어나는(min) t가 실제 교차입니다 (표준 slab 방식). 그 교차점 hitPos를 프로브 중심에서 바라본 방향으로 큐브맵을 읽으면, 가까운 벽은 가깝게·먼 벽은 멀게 비쳐 반사가 표면에 고정됩니다.

직관: 무한 큐브맵은 "벽이 무한히 멀다"고 가정합니다. parallax correction은 "아니, 이 방은 이만한 상자다"라는 거리 정보를 광선-상자 교차로 되살려, 시점을 옮기면 반사도 함께 흐르게(parallax) 만듭니다.

5-2. 프로브 블렌딩 — 경계에서 튀지 않게

한 표면이 여러 프로브의 영향 반경 안에 있으면, 가장 가까운 하나만 쓰면 프로브 경계를 넘을 때 반사가 탁 튑니다. 그래서 각 프로브에 가중치(중심에서 가까울수록·경계에서 멀수록 큼)를 주고 정규화해 섞습니다.

probe_blend.hlslhlsl
TextureCube gProbe[4] : register(t6);   // 영향 범위가 겹치는 프로브들(예: 4개)
cbuffer ProbeSetCB : register(b1)
{
    float4 gProbePos[4];     // .xyz = 프로브 중심, .w = 영향 반경
    float4 gProbeBox[8];     // (min0,max0, min1,max1, ...) parallax용 AABB
    int    gProbeCount;
};

float3 SampleBlendedProbes(float3 P, float3 R, float roughness)
{
    float3 acc = 0;  float wSum = 0;
    for (int i = 0; i < gProbeCount; ++i)
    {
        float  dist   = distance(P, gProbePos[i].xyz);
        float  radius = gProbePos[i].w;
        float  w      = saturate(1.0 - dist / radius);   // 경계(=반경)에서 0, 중심에서 1
        w *= w;                                          // 부드러운 폴오프
        if (w <= 0.0) continue;

        float3 Rc  = ParallaxCorrectR(P, R, gProbeBox[i*2].xyz, gProbeBox[i*2+1].xyz, gProbePos[i].xyz);
        acc  += gProbe[i].SampleLevel(gSamp, Rc, roughness * 5.0).rgb * w;
        wSum += w;
    }
    return wSum > 0.0 ? acc / wSum : gPrefilter.SampleLevel(gSamp, R, roughness*5.0).rgb; // 폴백=전역 IBL
}
실무 언리얼은 Sphere/Box Reflection Capture(정적, 미리 캡쳐)와 Planar Reflection(거울면), 그리고 실시간 Lumen 반사를 계층으로 섞습니다. 유니티는 Reflection Probe(Baked/Realtime)와 스카이박스 앰비언트를 프로브 볼륨으로 블렌딩합니다. 공통 원칙은 이 절과 같습니다 — parallax로 위치를 고치고, 가중치로 프로브를 섞고, 반경 밖은 전역 IBL로 폴백.
함정 — SSR과의 관계 리플렉션 프로브는 미리 구운 저해상도·지연 갱신이라 움직이는 물체·정확한 접촉 반사는 못 담습니다. 반대로 스크린 스페이스 반사(SSR)는 화면에 보이는 동적 픽셀을 정확히 반사하지만 화면 밖·가려진 것은 못 씁니다. 그래서 실무는 둘을 폴백 체인으로 씁니다: SSR을 먼저 시도 → 광선이 화면을 벗어나거나 히트 실패 → 리플렉션 프로브로 폴백 → 그것도 없으면 전역 IBL. SSR의 신뢰도(화면 안 히트 여부)로 두 결과를 블렌딩하면 이음매가 사라집니다.

6. 마무리 — 무엇을 언제 쓰나

상황추천 조합
정적 실외·하늘 하나전역 IBL(irradiance + 프리필터 + BRDF LUT) 한 세트
실내·구역별 다른 환경리플렉션 프로브 여러 개 + parallax correction + 블렌딩
동적 접촉 반사가 중요SSR 우선 → 프로브 폴백 → 전역 IBL 폴백
동적 하늘·시간대 변화디퓨즈는 SH 프로브로 매 프레임 갱신, 스페큘러만 프리필터 재굽기

IBL은 결국 PBR의 반구 적분을 오프라인으로 미룬 것입니다 — 디퓨즈는 irradiance 큐브맵으로, 스페큘러는 split-sum(프리필터 × BRDF LUT)으로 나눠 굽고, 리플렉션 프로브로 공간마다 배치합니다. 이 페이지가 다룬 것은 간접 스페큘러의 정석입니다. 간접 디퓨즈를 공간에 촘촘히 배치하는 라이트 프로브·DDGI는 전역 조명(GI)에서, 화면 공간 폴백은 스크린 스페이스 효과에서 이어집니다.
