Visibility Buffer — 삼각형 ID를 그리고 재질은 미룬다

디퍼드 렌더링은 조명을 미뤘습니다. Visibility Buffer는 한 걸음 더 나아가 재질(텍스처·셰이딩)까지 미룹니다. 지오메트리 패스는 픽셀마다 두꺼운 재질 데이터를 쓰는 대신 "이 픽셀에 어느 삼각형이 보이나"라는 아주 작은 정보 — (instanceID, triangleID) — 한 조각만 정수 텍스처 한 장에 기록합니다. 그리고 나중에 풀스크린 셰이딩 패스에서 그 ID로 삼각형의 정점을 셰이더에서 직접 되찾아 barycentric으로 속성을 재보간하고, 그때서야 재질을 샘플·셰이딩합니다. "무엇이 보이나(visibility)"와 "어떻게 셰이딩하나(material)"를 완전히 갈라, 지오메트리 패스의 대역폭을 픽셀당 20바이트에서 4~8바이트로 급감시키는 것이 이 경로의 핵심입니다. 특히 4K처럼 픽셀이 많고 재질이 다양할수록 이깁니다. 이 페이지에서는 ID 기록 셰이더와 재질 리졸브 셰이더를 흐름 한 줄, 함정 하나까지 해부합니다.

규약 이 시리즈는 D3D 규약으로 통일합니다: 행벡터 v' = v * M(HLSL mul(v, M)), 행렬 행 우선 저장, 왼손 좌표계, 클립 공간 z ∈ [0, 1], 텍스처 V축은 위→아래입니다. Visibility Buffer는 정점 데이터를 셰이더에서 직접 인덱싱하므로, CPU가 올리는 정점·인덱스 버퍼의 레이아웃과 셰이더의 페치 코드가 바이트 단위로 일치해야 합니다.

1. 원리 — G-buffer의 대역폭을 어떻게 줄이나

직관부터. 디퍼드의 G-buffer는 "재료를 미리 다 인화해 둔 사진 여러 장"입니다. 픽셀마다 위치·법선·알베도· 스페큘러 같은 두꺼운 재질 데이터를 씁니다. 디퍼드 페이지에서 손으로 세어 봤듯, 위치 8B + 법선 8B + 알베도스펙 4B = 픽셀당 약 20바이트. 지오메트리 패스에서 이걸 쓰고, 라이팅 패스에서 또 읽습니다. 화면이 클수록(4K = 830만 픽셀) 이 메모리 대역폭이 프레임의 발목을 잡습니다.

Visibility Buffer의 발상은 이렇습니다: 지오메트리 패스가 굳이 재질을 미리 풀어 쓸 이유가 없다. 그 픽셀에 무엇이 보이는지만 알면, 재질은 나중에 그 자리에서 다시 계산해 낼 수 있습니다. 그래서 지오메트리 패스는 픽셀당 아주 작은 것만 저장합니다 — (instanceID, triangleID), 혹은 drawID + primitiveID를 단일 R32_UINT(정수 텍스처) 한 장에 패킹해서. 픽셀당 4~8바이트면 끝입니다.

  1. 지오메트리(가시성) 패스: 씬을 한 번 그리되, 픽셀 셰이더는 색을 계산하지 않고 이 삼각형의 ID (instanceID와 래스터라이저가 주는 SV_PrimitiveID)를 uint 하나로 패킹해 R32_UINT 타깃에 기록합니다. 깊이 테스트로 가장 앞의 삼각형 ID만 남습니다.
  2. 재질(리졸브) 패스: 풀스크린으로, 각 화면 픽셀의 uint ID를 읽어 instanceID/triID로 언패킹합니다.
  3. 정점 되찾기: 그 삼각형의 세 정점 인덱스를 인덱스 버퍼(StructuredBuffer)에서 읽고, 정점 버퍼에서 위치·uv·법선을 셰이더가 직접 인덱싱해 가져옵니다.
  4. barycentric 재보간: 화면 픽셀 위치가 그 삼각형 안 어디쯤인지를 무게 (w0, w1, w2)로 구해, 정점 속성(uv·법선)을 가중합으로 재구성합니다.
  5. 재질·라이팅: 재구성한 uv로 재질 텍스처를 샘플하고, 그제서야 조명을 계산해 화면에 출력합니다.
직관 G-buffer가 "픽셀마다 재료를 미리 다 풀어 놓은 창고"라면, Visibility Buffer는 픽셀마다 영수증 번호 하나만 적어 둡니다. 재료가 필요해지는 순간(셰이딩 패스)에 그 번호로 원본 장부(정점·인덱스 버퍼)를 되짚어 필요한 만큼만 꺼냅니다. 창고를 통째로 채우고 비우는 대역폭이 사라지는 대신, 나중에 장부를 뒤지는 수고(정점 페치)가 생깁니다.

1-1. barycentric으로 속성을 되살리는 원리

직관부터. 삼각형 하나 안의 어떤 점이든 세 꼭짓점의 "섞음 비율"로 표현됩니다. 점이 꼭짓점 0에 붙어 있으면 0의 비율이 1이고 나머지는 0, 정중앙이면 셋이 각 1/3씩. 이 세 비율이 barycentric 좌표 (w0, w1, w2)이고, 항상 w0 + w1 + w2 = 1입니다.

그래서 삼각형 위 한 점의 속성(예: uv)은 세 꼭짓점 속성의 가중합으로 되살립니다: 

uv = w0 * uv0 + w1 * uv1 + w2 * uv2;   // 속성 = 세 정점 속성의 무게 섞음

보통은 래스터라이저가 이 보간을 대신 해 줍니다. Visibility Buffer는 래스터라이저를 건너뛰고 셰이딩 패스에서 손으로 barycentric을 계산합니다. 다만 함정이 하나 있습니다. 화면(스크린) 공간에서 선형으로 섞으면 원근이 어긋납니다. 원근 투영을 거치면 멀리 있는 정점일수록 화면에서 눌리기 때문에, 화면상 선형 무게를 그대로 쓰면 텍스처가 늘어나 보입니다. 그래서 각 무게를 정점의 1/w(클립 공간 w, 즉 원근 깊이)로 나눠 다시 정규화하는 perspective-correct 보정이 필요합니다. 래스터라이저가 자동으로 해 주던 그 보정을 여기선 직접 해야 합니다.

2. 직관 데모 — ID 버퍼 → 재질 2단계

같은 삼각형 메시를 2단계로 나눠 봅니다. 1단계(ID 버퍼)는 각 삼각형을 자기 ID를 나타내는 단색 인덱스 색으로만 채웁니다 — 재질 텍스처는 아직 없고, 픽셀당 저장되는 건 ID 하나뿐이라는 느낌입니다. 2단계(재질)는 같은 형상을 ID로 되찾아 실제 재질(음영·무늬)로 다시 칠합니다. 버튼으로 두 단계를 오가며 "같은 형상이 ID → 재질로 바뀌는" 흐름을 보세요. 왼쪽 위 HUD의 막대는 지오메트리 패스 저장량을 G-buffer(20B/픽셀)와 비교합니다.

저장: —
1단계에서 각 삼각형은 ID 색(정수 ID를 색으로 매핑)으로만 칠해집니다 — 픽셀당 ID 4B. 2단계에서 같은 ID로 삼각형을 되찾아 재질(그라디언트 음영)을 입힙니다.

4. 구현 — ID 기록과 재질 리졸브

두 셰이더가 전부입니다. (1) 지오메트리 패스가 삼각형 ID를 uint로 패킹해 기록하고, (2) 풀스크린 리졸브 패스가 그 ID로 정점을 되찾아 재질을 칠합니다.

4-1. 가시성 기록 — ID를 uint 하나로 패킹

지오메트리 패스의 픽셀 셰이더는 딱 한 줄이 핵심입니다. 인스턴스 ID(정점 셰이더가 넘겨준 SV_InstanceID)를 위쪽 비트로, 래스터라이저가 채워 주는 삼각형 번호(SV_PrimitiveID)를 아래쪽 비트로 비트 시프트·OR 해서 uint 하나에 담고, 그걸 R32_UINT 타깃에 씁니다.

vbuffer_write.hlsl (픽셀 셰이더)hlsl
// 삼각형 번호(primitiveID)에 몇 비트를 줄지. 예: 24비트면 삼각형 ~1600만 개까지.
#define TRI_BITS 24u

struct PSIn {
    float4 posH       : SV_Position;   // 깊이 테스트용 (가장 앞 삼각형만 남음)
    uint   instanceID : INSTANCEID;    // 정점 셰이더가 SV_InstanceID를 실어 보냄
};

// 출력은 색이 아니라 "가시성 ID" 정수 하나. 타깃 포맷은 R32_UINT.
uint main(PSIn i, uint primID : SV_PrimitiveID) : SV_Target
{
    // (instanceID << TRI_BITS) | primitiveID  →  단일 uint에 둘을 패킹
    uint id = (i.instanceID << TRI_BITS) | (primID & ((1u << TRI_BITS) - 1u));
    return id;   // 깊이 테스트가 알아서 최전면 삼각형의 ID만 남긴다
}
  • SV_PrimitiveID — 래스터라이저가 공짜로 주는 삼각형 번호입니다. 드로우 안에서 몇 번째 삼각형인지.
  • instanceID — 어느 인스턴스(어느 메시)인지. GPU-driven이면 drawID로 대체할 수 있습니다.
  • (instanceID << TRI_BITS) | primID — 위 비트에 인스턴스, 아래 비트에 삼각형을 넣어 uint 하나로 합칩니다. 리졸브 패스에서 반대로 시프트·마스크해 언패킹합니다.

4-2. 재질 리졸브 — 정점 되찾아 barycentric 재보간

풀스크린 셰이딩 패스입니다. 화면 픽셀의 uint ID를 읽어 언패킹하고, 그 삼각형의 세 정점을 버퍼에서 직접 인덱싱해 가져온 뒤, 화면 위치로 barycentric 무게를 구해 속성을 원근 보정해 재구성합니다. 그다음에야 재질 텍스처를 샘플하고 라이팅합니다.

vbuffer_resolve.hlsl (풀스크린 픽셀 셰이더)hlsl
#define TRI_BITS 24u

// 가시성 버퍼(정수 ID 한 장)
Texture2D<uint> visBuffer : register(t0);

// 씬의 원본 지오메트리를 셰이더에서 직접 인덱싱한다 (GPU-driven 스타일)
struct Vertex { float3 pos; float3 nrm; float2 uv; };
StructuredBuffer<uint>    indexBuffer  : register(t1);  // 삼각형 3개마다 정점 인덱스
StructuredBuffer<Vertex>  vertexBuffer : register(t2);  // 정점 속성
StructuredBuffer<float4x4> instanceMVP : register(t3);  // 인스턴스별 MVP 행렬

Texture2D    albedoTex : register(t4);
SamplerState samp      : register(s0);

float4 main(float4 posH : SV_Position, float2 uv : TEXCOORD0) : SV_Target
{
    // 1) 이 화면 픽셀의 가시성 ID를 읽는다 (정수 텍스처는 Load로 읽음)
    uint id = visBuffer.Load(int3((int2)posH.xy, 0));
    if (id == 0xFFFFFFFFu) discard;             // 빈 하늘 등: 그린 삼각형 없음

    // 2) 언패킹: 위 비트=인스턴스, 아래 비트=삼각형 번호
    uint instanceID = id >> TRI_BITS;
    uint triID      = id & ((1u << TRI_BITS) - 1u);

    // 3) 그 삼각형의 세 정점 인덱스를 인덱스 버퍼에서 읽는다
    uint i0 = indexBuffer[triID * 3u + 0u];
    uint i1 = indexBuffer[triID * 3u + 1u];
    uint i2 = indexBuffer[triID * 3u + 2u];

    // 4) 정점 버퍼에서 세 정점의 속성을 직접 페치
    Vertex v0 = vertexBuffer[i0];
    Vertex v1 = vertexBuffer[i1];
    Vertex v2 = vertexBuffer[i2];

    // 5) 세 정점을 클립 공간으로 다시 투영 (이 인스턴스의 MVP로)
    float4x4 mvp = instanceMVP[instanceID];
    float4 c0 = mul(float4(v0.pos, 1.0), mvp);   // 행벡터 규약: mul(v, M)
    float4 c1 = mul(float4(v1.pos, 1.0), mvp);
    float4 c2 = mul(float4(v2.pos, 1.0), mvp);

    // 6) 이 픽셀의 화면 좌표(NDC)에서 barycentric 무게 (w0,w1,w2) 계산
    //    posH.xy(픽셀) → NDC로 바꾼 뒤 삼각형 내부 무게를 구한다.
    float2 ndc = float2(posH.x / screenW * 2.0 - 1.0,
                        1.0 - posH.y / screenH * 2.0);   // V축 위→아래 보정
    float3 bary = BarycentricNDC(ndc, c0, c1, c2);       // 아래 함정 참고

    // 7) perspective-correct 보정: 각 무게를 클립 w로 나눠 다시 정규화
    float3 pw = bary / float3(c0.w, c1.w, c2.w);
    pw /= (pw.x + pw.y + pw.z);                           // 합이 1이 되도록

    // 8) 속성 재보간: 세 정점 속성의 (보정된) 가중합
    float2 fUV  = pw.x * v0.uv  + pw.y * v1.uv  + pw.z * v2.uv;
    float3 fNrm = normalize(pw.x * v0.nrm + pw.y * v1.nrm + pw.z * v2.nrm);

    // 9) 이제서야 재질 텍스처 샘플 + 라이팅
    float3 albedo = albedoTex.Sample(samp, fUV).rgb;
    float  ndotl  = saturate(dot(fNrm, normalize(float3(0.4, 0.8, 0.3))));
    float3 color  = albedo * (0.15 + 0.85 * ndotl);      // 앰비언트 + 확산
    return float4(color, 1.0);
}

핵심 흐름을 다시 짚으면: ID 읽기(1) → 언패킹(2) → 정점 인덱스 페치(3~4) → 다시 투영(5) → barycentric(6) → 원근 보정(7) → 속성 재보간(8) → 재질·라이팅(9). 래스터라이저가 자동으로 해 주던 "정점 속성 보간"을 셰이딩 패스에서 손으로 다시 하는 것이 전부입니다. screenW/screenH와 BarycentricNDC는 상수 버퍼·헬퍼로 넣는 자리표시자이고, 골격의 데이터 흐름은 그대로 컴파일 가능한 형태입니다.

함정 두 가지를 가장 많이 틀립니다. (1) perspective-correct 보정을 빠뜨리면 — 7번 단계를 생략하고 화면 선형 무게를 그대로 쓰면 — 원근이 있는 표면에서 텍스처가 비스듬히 늘어나거나 휘어 보입니다. 래스터라이저는 이 보정을 항상 해 주기 때문에 포워드에선 겪을 일이 없지만, 수동 재보간에선 반드시 챙겨야 합니다. (2) ID 패킹의 비트 폭이 부족하면 — 예컨대 TRI_BITS를 너무 작게 잡으면 — 삼각형이 많은 메시에서 번호가 오버플로해 엉뚱한 정점을 페치하고 픽셀이 튑니다. 인스턴스 수와 인스턴스당 최대 삼각형 수를 먼저 세고 비트 배분을 정하세요.
성능 리졸브 패스의 정점 수동 페치는 StructuredBuffer에 대한 랜덤 액세스라 캐시에 불리한 부담입니다. 그런데도 Visibility Buffer가 이기는 이유는, 지오메트리 패스에서 넓은 G-buffer를 쓰고 읽던 대역폭 절감이 그 페치 비용을 크게 압도하기 때문입니다 — 특히 4K처럼 픽셀이 많을수록. 또 씬 지오메트리를 큰 버퍼로 통합해 두는 GPU-driven 렌더링(간접 드로우·메시 클러스터)과 궁합이 좋아, drawID + primitiveID만으로 어떤 정점이든 찾아갈 수 있습니다.

5. 언제 쓰나 — 실무 노트

실무 이 경로의 원조는 Christoph Schied & Carsten Dachsbacher, "The Visibility Buffer"(2013)로, "캐시 친화적 디퍼드 셰이딩"을 목표로 삼각형 ID만 저장하는 아이디어를 정식화했습니다. 이후 Sebastian Aaltonen(당시 Ubisoft)이 Deferred Texturing이라는 이름으로 GPU-driven 파이프라인과 엮어 실전화했고(강연·트윗 다수), 재질 평가를 완전히 화면 공간으로 미루는 흐름을 대중화했습니다. 오늘날 가장 눈에 띄는 채택은 Nanite(UE5)로, 소프트웨어 래스터라이즈로 만든 visibility buffer 위에서 별도의 material pass가 재질을 리졸브합니다. The Filmic Games, Activision 계열 엔진에서도 비슷한 구조가 보고됩니다. 고해상도(4K)·수백만 인스턴스·GPU-driven 파이프라인이라면 강력한 후보입니다. 반대로 재질 종류가 적고 해상도가 중간이라면 평범한 디퍼드가 더 단순하고 충분합니다.
