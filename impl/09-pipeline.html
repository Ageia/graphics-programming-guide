Rendering Pipeline

Clear · Shadow · G-buffer · Lighting · Bloom · Tonemap

렌더 파이프라인 통합

이 장은 지금까지 배운 조각들이 한 프레임 안에서 어떻게 하나로 엮이는가를 보여주는 캡스톤입니다. 깊이 버퍼(3장)·조명(3장)·섀도우 맵(6장)·디퍼드 G-buffer(6장)·HDR 톤매핑(6장)·감마(7장)가 전부 정해진 순서의 패스(pass)로 이어져 최종 화면 한 장을 만듭니다. 개념 트랙 데모와 패스 순서·이름을 정확히 맞춰, 지연 셰이딩(deferred) 파이프라인을 Clear → Shadow → G-buffer → Deferred Lighting → Bloom → Tonemap+Gamma 여섯 단계로 C++/Direct3D 11/HLSL로 바인딩 한 줄, 리소스 상태 하나까지 구현합니다.

규약 이 페이지는 D3D 규약으로 통일합니다: 행벡터 v' = v * M(HLSL mul(v, M)), 행렬 행 우선 저장, 왼손 좌표계, 클립 z ∈ [0,1], 텍스처 V축 위→아래. 파이프라인은 개념 트랙 데모와 동일한 6패스 순서를 그대로 코드로 옮깁니다. G-buffer 구성·라이팅 셰이더의 성분별 해부는 디퍼드 렌더링(6장) 세부 페이지에서 이미 다뤘으니, 이 장은 패스들을 하나의 프레임으로 오케스트레이션하는 뼈대에 집중합니다.
가장 중요한 한 문장 파이프라인의 본질은 셰이더가 아니라 "무엇을 무엇에 그리고, 그 결과를 다음 패스가 어떻게 읽는가"라는 렌더 타깃(RTV)↔셰이더 리소스(SRV)의 릴레이입니다. 각 패스는 앞 패스의 출력 텍스처를 입력으로 받아 다음 텍스처를 채우고, 마지막 톤맵 패스만 백버퍼(화면)에 씁니다.

0. 한 프레임의 여섯 패스

매 프레임 아래 여섯 패스가 순서대로 실행됩니다. 각 패스가 어떤 텍스처를 쓰고(RTV) 어떤 텍스처를 읽는지(SRV)가 파이프라인의 전부입니다. 개념 트랙 데모의 타임라인과 정확히 같은 순서입니다.

#패스출력(RTV)입력(SRV)핵심
1ClearG-buffer 3장 + 깊이 + HDR—지난 프레임 흔적 제거
2Shadow MapshadowDepth—빛 시점 깊이 렌더
3G-bufferAlbedo·Normal·Position (MRT)재질 텍스처표면 속성 기록
4Deferred LightingHDR (sceneHDR)G-buffer 3장 + shadowDepth조명·그림자 합산
5BloombloomTex (ping-pong)sceneHDR → 블러 결과밝은 부분 번짐
6Tonemap + GammaBackbuffersceneHDR + bloomTexACES + 감마 → 화면
  1. 준비(1회): G-buffer 3장·HDR·Bloom ping-pong·섀도우 깊이 텍스처와 각각의 RTV/SRV/DSV, 풀스크린 삼각형·상태 객체를 미리 만든다.
  2. Clear: 이번 프레임에 쓸 모든 렌더 타깃과 깊이 버퍼를 지운다.
  3. Shadow → G-buffer → Lighting → Bloom → Tonemap: 패스마다 RTV를 세팅해 그리고, 그 출력을 SRV로 다음 패스에 넘긴다.
  4. Present: 톤맵 결과가 담긴 백버퍼를 스왑체인으로 표시한다.
함정 같은 텍스처를 RTV로 바인딩한 채 SRV로도 읽을 수 없습니다. D3D11 디버그 레이어가 "resource is bound as both input and output"으로 경고하고 한쪽을 자동 언바인드합니다. 그래서 각 패스는 다음 패스로 넘어가기 직전 자신의 RTV를 반드시 풀어(다음 OMSetRenderTargets로 교체) 그 텍스처를 SRV로 읽을 수 있게 만듭니다. 순서가 곧 규칙입니다.

0-1. 프레임 함수 뼈대 (C++)

아래가 이 장 전체의 척추입니다. 여섯 함수 호출이 곧 여섯 패스이고, 나머지 절에서 하나씩 채웁니다. 각 헬퍼는 "RTV 세팅 → 뷰포트 → 셰이더/리소스 바인딩 → 드로우"라는 같은 리듬을 따릅니다.

renderer.cpp — RenderFrame()cpp
void Renderer::RenderFrame() {
    ClearPass();          // 1) 모든 RTV/DSV 클리어
    ShadowPass();         // 2) 빛 시점 깊이 → shadowDepth
    GeometryPass();       // 3) 씬 → G-buffer(Albedo/Normal/Position) MRT
    LightingPass();       // 4) G-buffer + shadow → sceneHDR (풀스크린)
    BloomPass();          // 5) sceneHDR → bright → 분리형 가우시안 → bloomTex
    TonemapPass();        // 6) sceneHDR + bloomTex → ACES/감마 → 백버퍼
    swapChain->Present(1, 0);   // V-Sync
}

// 어떤 패스든 RTV를 바꿀 때 이전 SRV 바인딩을 먼저 푼다(위 함정 방지용 헬퍼)
void Renderer::UnbindPSSRVs(UINT count) {
    ID3D11ShaderResourceView* nulls[8] = {};   // 최대 8슬롯을 null로
    ctx->PSSetShaderResources(0, count, nulls);
}

1. Clear 패스

프레임의 첫 삽질입니다. 이번 프레임에 그릴 모든 렌더 타깃과 깊이 버퍼를 초기화해 지난 프레임의 잔상을 지웁니다. D3D11에서는 OpenGL의 glClear처럼 한 번에 다 지우는 함수가 없고, RTV마다 ClearRenderTargetView, 깊이는 ClearDepthStencilView를 각각 호출합니다.

ClearPass()cpp
void Renderer::ClearPass() {
    const float black[4] = { 0, 0, 0, 0 };

    // G-buffer 3장 + HDR 씬 타깃을 각각 클리어
    ctx->ClearRenderTargetView(gAlbedo.rtv.Get(),   black);
    ctx->ClearRenderTargetView(gNormal.rtv.Get(),   black);
    ctx->ClearRenderTargetView(gPosition.rtv.Get(), black);
    ctx->ClearRenderTargetView(sceneHDR.rtv.Get(),  black);
    ctx->ClearRenderTargetView(bloomA.rtv.Get(),    black);
    ctx->ClearRenderTargetView(bloomB.rtv.Get(),    black);

    // 깊이 버퍼: 가장 먼 값 1.0으로 (왼손·z[0,1] 규약에서 0=최근접, 1=최원거리)
    ctx->ClearDepthStencilView(sceneDSV.Get(),  D3D11_CLEAR_DEPTH, 1.0f, 0);
    ctx->ClearDepthStencilView(shadowDSV.Get(), D3D11_CLEAR_DEPTH, 1.0f, 0);

    // 백버퍼(최종 화면)도 클리어
    ctx->ClearRenderTargetView(backbufferRTV.Get(), black);
}

깊이를 1.0으로 지우는 이유는 3장(깊이 버퍼)에서 본 그대로입니다. 왼손 좌표계 + 클립 z∈[0,1] 규약에서 0이 카메라 최근접, 1이 최원거리이므로, 처음엔 "무한히 멀다"로 채워 두고 더 가까운 픽셀이 오면 갱신합니다. 이 패스에서는 아직 OMSetRenderTargets로 묶을 필요가 없습니다 — 클리어는 뷰만 있으면 됩니다.

성능 타일드/모바일 GPU에서는 클리어가 공짜에 가깝습니다(타일 시작 시 fast-clear). 반대로 클리어를 빼먹고 부분만 다시 그리는 "누적" 최적화는 타일 GPU에서 오히려 load 비용을 유발할 수 있습니다. 특별한 이유가 없으면 매 프레임 명시적으로 클리어하는 편이 안전합니다.

2. Shadow Map 패스

빛의 시점에서 씬을 렌더해 각 지점까지의 깊이를 텍스처에 기록합니다. 나중에 라이팅 패스가 "이 표면점이 빛에서 봤을 때 가려졌는가"를 이 텍스처와 비교해 판정합니다(6장 섀도우 맵과 동일 원리). 핵심은 카메라가 아니라 빛의 뷰·투영 행렬을 쓰고, 깊이 전용 렌더 타깃에 그린다는 점입니다.

ShadowPass()cpp
void Renderer::ShadowPass() {
    // 색 출력 없이 깊이만 그린다: RTV는 nullptr, DSV만 바인딩
    ctx->OMSetRenderTargets(0, nullptr, shadowDSV.Get());

    // 섀도우 맵 해상도에 맞춘 뷰포트 (보통 백버퍼보다 큼: 2048²)
    D3D11_VIEWPORT vp = { 0, 0, (float)SHADOW_SIZE, (float)SHADOW_SIZE, 0.0f, 1.0f };
    ctx->RSSetViewports(1, &vp);

    // 빛 시점 view*proj를 cbuffer로 (행벡터 규약 → 전치해 업로드)
    XMMATRIX lightVP = lightView * lightProj;
    UploadCB(cbShadow, XMMatrixTranspose(lightVP));

    ctx->VSSetShader(shadowVS.Get(), nullptr, 0);
    ctx->PSSetShader(nullptr, 0, 0);       // 깊이만 → 픽셀 셰이더 불필요
    ctx->RSSetState(shadowRS.Get());       // 슬로프 스케일 깊이 바이어스 적용
    DrawSceneMeshes();                     // 그림자를 드리우는 모든 메시

    ctx->RSSetState(nullptr);              // 컬/바이어스 상태 원복
}

깊이만 필요하므로 픽셀 셰이더를 아예 붙이지 않습니다(PSSetShader(nullptr,...)). 래스터라이저가 깊이만 shadowDSV에 써 주기 때문입니다. 이렇게 하면 그림자 패스가 매우 가볍습니다. 빛 시점 view·proj 행렬은 방향광이면 XMMatrixOrthographicLH(직교), 점/스팟광이면 XMMatrixPerspectiveFovLH로 만듭니다.

함정 섀도우 깊이 텍스처는 깊이 포맷과 SRV 포맷을 분리해야 합니다. 텍스처는 DXGI_FORMAT_R24G8_TYPELESS로 만들고, DSV는 D24_UNORM_S8_UINT, SRV는 R24_UNORM_X8_TYPELESS로 각각 다른 뷰 포맷을 지정합니다. BindFlags에는 DEPTH_STENCIL | SHADER_RESOURCE를 함께 켜야 라이팅 패스에서 SRV로 읽을 수 있습니다.
성능 슬로프 스케일 깊이 바이어스(D3D11_RASTERIZER_DESC::SlopeScaledDepthBias)를 켜서 표면과 그림자가 스스로 그림자를 드리우는 섀도우 애크니(shadow acne)를 줄입니다. 너무 크게 주면 반대로 그림자가 물체에서 떨어져 뜨는 피터 패닝(peter panning)이 생기니 절충이 필요합니다.

3. G-buffer 패스 (MRT)

씬의 모든 메시를 카메라 시점으로 한 번 그리되, 색을 화면에 바로 내보내는 대신 각 픽셀의 Albedo·Normal·Position을 세 장의 렌더 타깃에 동시에 기록합니다 (MRT, Multiple Render Targets). 개념 트랙 데모의 G-buffer · Albedo/Normal/Position 세 채널과 정확히 대응합니다. 텍스처·RTV·SRV 생성과 HLSL SV_Target0..2 출력의 성분별 해부는 6장 디퍼드 렌더링에 있으니, 여기서는 패스로서의 바인딩만 봅니다.

GeometryPass()cpp
void Renderer::GeometryPass() {
    // 세 RTV를 하나의 배열로 묶어 MRT 활성화 (순서 = SV_Target0/1/2)
    ID3D11RenderTargetView* rtvs[3] = {
        gAlbedo.rtv.Get(), gNormal.rtv.Get(), gPosition.rtv.Get()
    };
    ctx->OMSetRenderTargets(3, rtvs, sceneDSV.Get());

    // 카메라 해상도 뷰포트로 복귀 (섀도우 패스에서 2048²로 바꿨으므로)
    D3D11_VIEWPORT vp = { 0, 0, (float)W, (float)H, 0.0f, 1.0f };
    ctx->RSSetViewports(1, &vp);

    ctx->OMSetDepthStencilState(depthWriteOn.Get(), 0);  // 깊이 쓰기 ON
    ctx->VSSetShader(gbufferVS.Get(), nullptr, 0);
    ctx->PSSetShader(gbufferPS.Get(), nullptr, 0);
    DrawSceneMeshes();       // 각 픽셀 속성이 세 타깃에 기록됨

    // 다음(라이팅) 패스가 이 셋을 SRV로 읽으려면 RTV를 먼저 풀어야 한다
    ID3D11RenderTargetView* none[3] = { nullptr, nullptr, nullptr };
    ctx->OMSetRenderTargets(3, none, nullptr);
}

rtvs[] 배열의 순서(0=Albedo, 1=Normal, 2=Position)가 곧 HLSL 픽셀 셰이더의 SV_Target0/1/2와 짝입니다. 순서를 뒤섞으면 위치 텍스처에 색이 들어가는 대참사가 납니다. 패스 끝에서 RTV를 nullptr로 다시 세팅해 언바인드하는 마지막 두 줄이 이 장의 핵심 습관입니다 — 이게 없으면 라이팅 패스에서 같은 텍스처를 SRV로 못 읽습니다.

함정 MRT로 묶는 세 타깃과 깊이 버퍼는 같은 해상도·같은 샘플 수(MSAA)여야 합니다. 하나라도 다르면 D3D가 바인딩을 거부합니다. 또한 섀도우 패스에서 RSSetViewports를 2048²로 바꿨으므로 여기서 카메라 해상도로 다시 세팅하지 않으면 G-buffer가 화면 일부에만 그려집니다(자주 하는 실수).

4. Deferred Lighting 패스

화면을 덮는 풀스크린 삼각형 하나를 그리면서, G-buffer 세 장과 섀도우 맵을 SRV로 읽어 픽셀마다 조명을 계산합니다. 결과는 화면(백버퍼)이 아니라 HDR 렌더 타깃(sceneHDR)에 씁니다 — 블룸과 톤매핑이 뒤에 남아 있으므로 아직 0~1로 눌러선 안 되기 때문입니다.

LightingPass()cpp
void Renderer::LightingPass() {
    // 출력 = HDR 타깃 (백버퍼가 아니다). 깊이 테스트 불필요 → DSV 없음
    ctx->OMSetRenderTargets(1, sceneHDR.rtv.GetAddressOf(), nullptr);

    // 입력 = G-buffer 3장(t0,t1,t2) + 섀도우 깊이(t3)를 순서대로 바인딩
    ID3D11ShaderResourceView* srvs[4] = {
        gAlbedo.srv.Get(), gNormal.srv.Get(), gPosition.srv.Get(), shadowSRV.Get()
    };
    ctx->PSSetShaderResources(0, 4, srvs);
    ctx->PSSetSamplers(0, 1, pointClamp.GetAddressOf());
    ctx->PSSetSamplers(1, 1, shadowCmp.GetAddressOf());   // 비교 샘플러(PCF)

    UploadCB(cbLighting, lightData, lightVP_forShadow);
    DrawFullscreenTriangle(lightingVS, lightingPS);

    UnbindPSSRVs(4);   // 다음 패스가 sceneHDR을 읽으려면 여기 SRV들도 풀기
}
lighting_pass.hlsl (픽셀 셰이더 발췌)hlsl
Texture2D gAlbedo   : register(t0);
Texture2D gNormal   : register(t1);
Texture2D gPosition : register(t2);
Texture2D gShadow   : register(t3);
SamplerState samp         : register(s0);
SamplerComparisonState sCmp : register(s1);

float3 main(float4 posH : SV_Position, float2 uv : TEXCOORD0) : SV_Target {
    float3 albedo = gAlbedo.Sample(samp, uv).rgb;
    float3 N      = normalize(gNormal.Sample(samp, uv).xyz);
    float3 P      = gPosition.Sample(samp, uv).xyz;     // 월드 위치

    // --- 그림자 판정: 표면점을 빛 클립공간으로 투영해 깊이 비교 ---
    float4 lp = mul(float4(P, 1.0), gLightVP);
    float2 suv = lp.xy / lp.w * float2(0.5, -0.5) + 0.5; // 클립→UV, V 뒤집기
    float  curDepth = lp.z / lp.w;
    float  shadow = gShadow.SampleCmpLevelZero(sCmp, suv, curDepth - 0.001); // PCF

    // --- 확산 + 스페큘러 (Blinn-Phong) ---
    float3 L = normalize(gLightPos - P);
    float  diff = max(dot(N, L), 0.0);
    float3 V = normalize(gCamPos - P);
    float3 H = normalize(L + V);
    float  spec = pow(max(dot(N, H), 0.0), 32.0);

    float3 lit = albedo * 0.05                         // 앰비언트
               + (diff * albedo + spec) * gLightColor * shadow;
    return lit;   // HDR: 1.0을 넘을 수 있음 (다음 패스에서 톤맵)
}

조명 결과가 1.0을 넘어도 그대로 둡니다. HDR 타깃(R16G16B16A16_FLOAT)이라 밝은 값을 잘리지 않고 보존하고, 이 초과분이 다음 블룸 패스의 재료가 됩니다. G-buffer/조명 공식의 성분별 유도는 6장 디퍼드에, 섀도우 비교 샘플러(PCF)는 6장 섀도우 맵에 상세합니다.

함정 라이팅 패스는 G-buffer를 SRV로 읽는 패스이므로, 3절 끝에서 G-buffer의 RTV를 반드시 풀어 둬야 합니다(안 풀면 자동 언바인드 + 경고). 반대로 이 패스가 끝나면 sceneHDR이 다음 블룸 패스의 입력이 되므로, 여기서도 UnbindPSSRVs로 입력 SRV들을 풀고 OMSetRenderTargets로 sceneHDR의 RTV를 교체합니다. 릴레이의 매 구간에서 이 스왑이 반복됩니다.

5. Bloom 패스

밝은 부분이 렌즈에서 번져 보이는 광채를 흉내 냅니다. 세 단계입니다: (1) bright pass로 임계값 이상의 밝은 픽셀만 추출하고, (2) 가로·세로로 나눈 분리형 가우시안 블러를 두 텍스처(bloomA↔bloomB) 사이를 오가며(ping-pong) 여러 번 적용해 부드럽게 번지게 합니다. 결과 bloomTex는 톤맵 패스에서 더해집니다.

BloomPass()cpp
void Renderer::BloomPass() {
    // (1) bright pass: sceneHDR에서 임계값 이상만 bloomA로 추출
    ctx->OMSetRenderTargets(1, bloomA.rtv.GetAddressOf(), nullptr);
    ctx->PSSetShaderResources(0, 1, sceneHDR.srv.GetAddressOf());
    DrawFullscreenTriangle(fsVS, brightPS);      // 밝은 부분만 통과
    UnbindPSSRVs(1);

    // (2) 분리형 가우시안 블러: 가로→세로를 N회 ping-pong
    bool horizontal = true;
    for (int i = 0; i < BLOOM_ITER * 2; ++i) {
        GTarget& dst = horizontal ? bloomB : bloomA;
        GTarget& src = horizontal ? bloomA : bloomB;
        ctx->OMSetRenderTargets(1, dst.rtv.GetAddressOf(), nullptr);
        ctx->PSSetShaderResources(0, 1, src.srv.GetAddressOf());
        UploadCB(cbBlur, horizontal ? 1 : 0);    // 블러 방향
        DrawFullscreenTriangle(fsVS, blurPS);
        UnbindPSSRVs(1);
        horizontal = !horizontal;
    }
    // 마지막 dst(= bloomA 또는 bloomB)가 최종 bloomTex가 된다
}
blur.hlsl (1D 가우시안, 분리형)hlsl
Texture2D src : register(t0);
SamplerState samp : register(s0);
cbuffer BlurCB : register(b0) { float2 texel; float horizontal; float _pad; };

static const float w[5] = { 0.2270, 0.1946, 0.1216, 0.0540, 0.0162 };

float3 main(float4 p : SV_Position, float2 uv : TEXCOORD0) : SV_Target {
    float3 sum = src.Sample(samp, uv).rgb * w[0];
    float2 dir = horizontal > 0.5 ? float2(texel.x, 0) : float2(0, texel.y);
    [unroll] for (int i = 1; i < 5; ++i) {
        sum += src.Sample(samp, uv + dir * i).rgb * w[i];
        sum += src.Sample(samp, uv - dir * i).rgb * w[i];
    }
    return sum;
}

왜 분리형(separable)인가? 2D 가우시안 하나(예: 9×9=81탭)를 가로 9탭 + 세로 9탭 = 18탭 두 번으로 나누면 수학적으로 같은 결과를 훨씬 적은 샘플로 얻습니다. 이것이 ping-pong으로 방향을 번갈아 적용하는 이유입니다. 흔히 다운샘플한 절반/1/4 해상도 버퍼에서 블러해 비용을 더 줄입니다.

성능 블룸은 대역폭 바운드 패스라, 풀 해상도로 여러 번 돌리면 금세 무거워집니다. 실무에서는 (1) 1/2·1/4 다운샘플 체인에서 블러하고, (2) 양선형 샘플링으로 2탭을 1탭으로 합치는 (linear-sampling Gaussian) 최적화를 씁니다. 위 코드는 이해를 위한 풀 해상도·정탭 버전입니다.

6. Tonemap + Gamma 패스

마지막 패스입니다. sceneHDR + bloomTex를 더한 HDR 색을 ACES 톤맵 곡선으로 눌러 0~1 범위로 매핑하고, 감마 2.2를 적용해 백버퍼(화면)에 씁니다. 이 패스만 유일하게 최종 출력이 백버퍼입니다. HDR·톤매핑의 원리는 6장 HDR·톤매핑, 감마·선형 워크플로는 7장 감마에 상세합니다.

TonemapPass()cpp
void Renderer::TonemapPass() {
    ctx->OMSetRenderTargets(1, backbufferRTV.GetAddressOf(), nullptr);

    ID3D11ShaderResourceView* srvs[2] = { sceneHDR.srv.Get(), bloomTex.srv.Get() };
    ctx->PSSetShaderResources(0, 2, srvs);
    DrawFullscreenTriangle(fsVS, tonemapPS);
    UnbindPSSRVs(2);           // 다음 프레임 클리어 전에 정리
}
tonemap.hlslhlsl
Texture2D sceneHDR : register(t0);
Texture2D bloomTex : register(t1);
SamplerState samp  : register(s0);
cbuffer PostCB : register(b0) { float exposure; float bloomStrength; float2 _pad; };

// Narkowicz 2015 ACES 근사 (필름 룩)
float3 ACES(float3 x) {
    const float a = 2.51, b = 0.03, c = 2.43, d = 0.59, e = 0.14;
    return saturate((x * (a * x + b)) / (x * (c * x + d) + e));
}

float4 main(float4 p : SV_Position, float2 uv : TEXCOORD0) : SV_Target {
    float3 hdr = sceneHDR.Sample(samp, uv).rgb
               + bloomTex.Sample(samp, uv).rgb * bloomStrength;
    hdr *= exposure;                    // 노출
    float3 mapped = ACES(hdr);          // HDR → [0,1]
    mapped = pow(mapped, 1.0 / 2.2);    // 선형 → sRGB(감마)
    return float4(mapped, 1.0);
}

순서가 중요합니다: 블룸 합성 → 노출 → 톤맵 → 감마. 톤맵은 반드시 선형 공간의 HDR 값에 적용해야 하고, 감마 보정은 맨 마지막에 딱 한 번만 해야 합니다. 감마를 두 번 걸면(예: sRGB 백버퍼 포맷 + 셰이더 pow) 색이 씻겨 보이는 이중 보정 버그가 납니다(7장 참고).

함정 백버퍼 포맷이 _SRGB(예: R8G8B8A8_UNORM_SRGB)면 하드웨어가 자동으로 감마를 적용하므로 셰이더에서 pow(1/2.2)를 또 하면 안 됩니다. 둘 중 하나만 선택하세요. 위 코드는 비-sRGB 백버퍼를 가정해 셰이더에서 수동 감마를 겁니다.

7. 최적화 · 병목 노트

파이프라인을 다 엮고 나면, 어느 패스가 프레임을 잡아먹는지 프로파일러(RenderDoc·PIX·Nsight의 타임라인)로 보는 것이 다음 단계입니다. 병목은 대개 셋 중 하나입니다.

병목징후대표 원인 패스대응
정점(vertex)메시·인스턴스 수↑에 민감Shadow · G-bufferLOD·컬링(7장)·인스턴싱, 섀도우는 저폴리 프록시
픽셀(pixel)해상도·광원 수↑에 민감Lighting타일드/클러스터드로 픽셀당 광원 수 줄이기(6장 경로 비교)
대역폭(bandwidth)G-buffer·블룸 폭↑에 민감G-buffer · Bloom채널 패킹·깊이에서 위치 재구성·블룸 다운샘플

디퍼드 파이프라인의 장단점

  • 장점 — 조명 비용이 광원 수에 대해 확장: 조명이 보이는 화면 픽셀 × 광원에만 비례해, 오버드로우가 심하고 광원이 많은 씬에서 포워드보다 압도적으로 유리합니다.
  • 단점 — MSAA가 까다롭다: 에지 안티앨리어싱을 G-buffer 단계에서 처리하기 어려워, 보통 FXAA/TAA 같은 후처리 AA로 대체합니다(7장 안티앨리어싱).
  • 단점 — 반투명 처리 불가: G-buffer는 픽셀당 표면 하나만 담으므로, 반투명 물체는 라이팅 이후 별도 포워드 패스로 덧그립니다(7장 투명·정렬).
  • 단점 — 재질 다양성이 G-buffer 크기에 제한: 재질 파라미터가 늘면 타깃이 늘고 대역폭도 늡니다. 그래서 채널 패킹과 위치 재구성으로 G-buffer를 줄이는 것이 최적화의 절반입니다(6장 디퍼드).
성능 패스 간 배리어/전환 자체도 비용입니다. D3D11은 드라이버가 자동 동기화하지만, RTV↔SRV 전환마다 캐시 플러시가 일어날 수 있습니다. D3D12/Vulkan으로 가면 이 전환이 명시적 리소스 배리어가 되어 (5장 명시적 API) 직접 관리해야 하는데, 원리는 이 페이지의 "RTV 풀고 SRV로 바인딩"과 정확히 같습니다.
개념 트랙과의 대응 개념 트랙의 렌더 파이프라인 데모는 이 여섯 패스를 WebGL 오프스크린 FBO로 실제 렌더하며 타임라인을 드래그해 패스가 하나씩 쌓이는 과정을 보여줍니다. 이 페이지는 그 데모의 각 패스를 D3D11 바인딩과 HLSL 셰이더로 1:1 옮긴 것입니다. 데모의 썸네일 라벨(Shadow·Albedo·Normal·Position·Lit·Bloom)이 여기 각 절과 정확히 짝을 이룹니다.
